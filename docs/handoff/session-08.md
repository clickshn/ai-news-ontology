## 3. F4 — 단가는 **단계가 아니라 모델**에 붙는다

원래 코드는 `gate` 단계면 Haiku 단가, `extraction` 단계면 Opus 단가를 곱했다.
단계와 모델이 1:1 이던 동안에만 맞는 계산이고, **vLLM 이전(ADR-018) 이후로는
틀린다** — 같은 두 단계가 `gemma-4-31B-it` 로 도는데 벤더 달러가 계속 곱해진다.

### 세 칸을 갈랐다

| 값 | 뜻 |
|---|---|
| `claude-*` 단가 | 벤더 청구액 (`observability/README.md` 와 같은 출처) |
| `gemma-4-31B-it` → **`0.0`** | **등록된 사실** — 내부 vLLM 은 토큰당 청구가 없다 |
| 표에 없는 모델 → **`None`** | **모르는 것.** 보고서에 `단가 미등록` |

**`0.0` 과 미등록을 같은 0 으로 적으면 "공짜로 돌았다"와 "단가를 모른다"가 한 칸에
섞인다.** 그래서 소스 안에 단가 모르는 모델이 하나라도 있으면 그 소스의 소계는
`None` 이고, 합계 줄은 **뺀 건수와 뺀 이유를 같이 적는다** — 아는 부분만 더한 값에
"합계"라는 이름을 붙이면 뺀 만큼 싸 보인다. 아는 건이 0 이면 합계는 `$0.000` 이
아니라 `단가 미등록` 이다.

접두사 매칭은 `extraction/llm.py: MODEL_UNSUPPORTED_PARAMS` 와 **같은 기준**이다 —
거부하는 주체도 곱해지는 주체도 모델이고, 날짜 접미사를 버전마다 등록하지 않는다.

### 220건 추정치는 **바뀌지 않았다**

```
합계 30건 / $2.058 (건당 평균 $0.0686)   ← 수정 후 실행
```

보존된 30건이 **전부 벤더 실행**(추출 `claude-opus-5` 30건 / 게이트
`claude-haiku-4-5-20251001` 30건)이라 옛 매핑과 새 매핑이 같은 값을 준다.
session-01 §의 `220 × $0.0686 ≈ $15.1` 과 `observability/README.md` 의 수치를
**고칠 것이 없다.** 이 수정이 값을 바꾸는 것은 **다음 실행부터**다.

> 이 점이 F4 를 덜 중요하게 만들지 않는다. 틀린 계산이 **지금은 옳은 답을 내고
> 있었을 뿐**이고, 그 상태로 vLLM 실행을 집계했으면 없는 비용이 찍혔다.

## 4. F3 — 전송 실패는 **관측 실패**지 나쁜 관측이 아니다

`schema_failure_rate` 가 재려는 것은 **모델이 계약을 지켰는가**다(사전 등록 §3②).
전송이 실패한 건은 모델에게 **물어보지 못한 건**이다.

```
schema_failure_rate = schema_failures / (item_count − transport_failures)
                      ↑ SchemaMismatchError 만    ↑ measured_items
```

### 분모에서도 뺐다 — 두 방향이 다 틀린다

| 어떻게 세면 | 무엇이 틀리나 |
|---|---|
| 전송 실패를 **분자**에 (기존) | 회선이 나쁜 날의 실행이 **"모델이 스키마를 못 지킨다"** 로 기록된다 |
| 전송 실패를 **분모에만** 남기면 | 전송 실패가 늘수록 실패율이 **낮게** 나온다 — 재지 못한 것이 잘한 것으로 읽힌다 |

**D-050 과 같은 계산이다.** 한 건도 못 쟀으면 비율은 `0.0` 이 아니라 `None` 이고,
분모(`measured_items`)를 비율 옆에 같이 적는다 — 0.5 가 2건인지 200건인지 모르면
그 비율로 아무것도 정할 수 없다.

### 기존 측정 결과는 **다시 계산해도 같다** (확인함)

`data/replays/{main,sample}` 의 `rows.json` 을 새 `summarize_rows` 로 돌렸다.
실패가 **한 건도 없던 실행**이라 `schema_failures 0 / transport_failures 0 /
rate 0.0` 으로 기존 `summary.json` 과 **다른 칸이 없다.** ADR-018 Evidence 는
그대로 유효하다.

**기존 `summary.json` 을 재생성하지 않았다.** API 없이 `rows.json` 만으로 다시 쓸 수
있지만, 그건 **기록된 측정 결과를 사후에 고쳐 쓰는 일**이다. 새 칸 두 개가 없는
것은 그 실행이 그때 무엇을 셌는지를 그대로 보여 준다.

## 5. 설계 판단 — 왜 ADR 이 아닌가

**ADR 을 남기지 않았다.** session-06 · 07 과 같은 계산이다 — 새 의존성 0개, 외부
서비스 선택 아님, **MARA 가 읽는 출력 계약(JSONL·manifest) 불변.**

걸릴 만한 것 하나가 **`summary.json` 에 칸이 두 개 늘었다**는 것인데, 이 파일은
계약 산출물이 아니라 **이 레포 안의 측정 기록**이고 MARA 가 읽지 않는다. 기존
파일도 그대로 읽히며 수치가 바뀌지 않는 것을 §4 에서 확인했다. D-074~076 으로
남겼다. **다른 판단이었으면 `adr-skill:adr-recorder` 로 갔어야 한다** (F12).

- **`pytest-socket` 을 넣지 않았다.** 새 의존성이고, 어차피 루프백 예외 정책은
  우리가 써야 한다 — 그게 이 장치의 어려운 부분 전부다.
- **판정 로직을 `conftest.py` 에 두지 않았다.** pytest 가 `conftest` 로 import 하는데
  테스트가 `tests.conftest` 로 다시 import 하면 **모듈이 둘이 되고 예외 클래스도
  둘이 된다** — `pytest.raises` 가 자기가 만든 예외를 못 잡는다. 실제로 겪고 옮겼다.
- **비용을 `float | None` 로 열었다.** 예외로 올리면 보고서 한 줄 때문에 집계 전체가
  멈추고, 0 으로 접으면 F4 를 다른 모양으로 되풀이한다.
- **`MODEL_PRICES` 를 `config.yaml` 로 올리지 않았다.** D-070 과 같은 이유이고,
  단가의 출처는 `observability/README.md` 하나로 유지한다(미러를 늘리지 않는다).

## 8. 변이 검사 — **복사본에서 돌렸다**

`docs/governance.md` 에 이번에 넣은 규칙이 이것이다: **커밋되지 않은 작업본에
`git checkout` / `git restore` 를 쓰지 않는다.** 변이를 되돌리는 명령이 **같이 있던
미커밋 변경까지 되돌리고**, 복구 지점이 없어 그 작업이 통째로 사라진다.

원본 문자열로 한다 — git 을 쓰지 않으므로 작업본을 건드릴 수 없다.

## 주의 (이월, 여전히 유효)

- 테스트는 가상환경으로: `.venv/Scripts/python.exe -m pytest tests/ -q`.

- **변이 검사는 복사본이나 별도 worktree 에서.** 작업본에 `git checkout` 을 쓰지 않는다.
- 실행에 쓰인 프롬프트 버전은 **수정하지 않는다.** 새 버전 파일을 만든다.

  훅이 그 명령 자체를 차단한다.
- 셸 스크립트는 **LF** 로 유지한다. CRLF 면 훅이 조용히 안 돈다.
- **push 전에** `git log --oneline` 으로 확인한다.

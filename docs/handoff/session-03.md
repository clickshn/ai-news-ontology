## 2. 🚩 무엇이 뒤집혔나 — `test_blocked_state_run.py`

session-02 가 이 파일에 고정한 것은 **"승인 없이 돌리면 진입점이 벤더 호출 전에
멈춘다"** 였다. 그때는 맞았고, **멈추는 것이 이식 성공의 증거**였다.

**지금은 참이 아니다. 멈출 벤더 호출이 없다.** 되돌리지 않고 새 계약으로 갱신했다.

| 지금 고정하는 것 | 왜 |
|---|---|
| 모든 진입점이 벤더 클라이언트를 **만들지 않고 끝까지 돈다** | 여기서 `ExternalVendorCallError` 가 나오면 **벤더 지점이 남은 것**이다 |
| 만들어지는 클라이언트가 **내부 엔드포인트를 가리킨다** | "벤더를 안 부른다"와 "내부를 부른다"는 **다른 명제**다. 둘 다 확인해야 이전이 끝난 것 |
| 설정에 벤더 모델명이 남아 있지 않다 | 되돌아갔는지를 설정 층에서 본다 |
| **되돌리면 게이트가 여전히 잡는다** | `llm.provider` 한 줄로 되돌아가므로 ADR-017 의 보장이 살아 있는지를 같은 파일에서 고정 |

네트워크는 여전히 **0건**이다. 피드는 픽스처로, vLLM 호출은 `VLLMClient._post` 스텁으로
대체하고 **소켓 트립와이어는 그대로 뒀다.**

> **벤더 호출 지점: 5 → 0.** 이것이 이전 완료의 판정이고, 남은 것은 없다.

## 3. 🔴 ADR-019 — 이 엔드포인트의 성질을 먼저 알고 써야 한다

**모르는 파라미터를 400 으로 거절하지 않고 조용히 무시한다. HTTP 200 이 온다.**

| 파라미터 | 결과 |
|---|---|
| `response_format={"type":"json_schema"}` | **강제됨. 이 레포는 이것만 쓴다** |
| `structured_outputs={"json": …}` | 강제됨 (쓰지 않는다 — 하나로 고정) |
| `guided_json=…` | ⛔ **무시됨.** vLLM 문서에 흔한 이름이라 검색으로 흘러 들어오기 쉽다 |
| 존재하지 않는 이름 | 무시됨. **`guided_json` 과 결과가 같다** |

**`guided_json` 으로 썼으면 이번 측정 전체가 "강제 없는 gemma"를 잰 것이 되고,
알 방법이 없었다.**

### 판별은 "스키마를 어겨 보라"가 아니라 **"JSON 을 쓰지 마라"**

첫 probe 를 전자로 짰다가 **정반대 결론이 나올 뻔했다.** `minLength:200` 이 문자열을
못 닫게 강제해서 깨진 JSON 이 나왔는데, 그게 "문법이 뚫렸다"로 읽혔다. 실제로는
`finish_reason: "length"` — **강제가 너무 잘 걸려서** 깨진 것이었다.

> **모델의 순종도와 디코더의 강제는 출력만 보고 구분되지 않는다.**
> "JSON 쓰지 마라"는 둘이 **반대 방향**을 가리키게 만든다 — 산문이 나오면 강제가
> 아니고, 스키마에 맞는 JSON 이 나오면 강제다. 다른 해석이 없다.

절차는 `.claude/rules/vllm-endpoint.md`. **엔드포인트·모델·서버가 바뀌면 다시 돌린다.**

## 4. 🚩 측정이 실제로 잰 것 — 합격이지만 읽는 법이 중요하다

전문은 `docs/eval/run-log-session-03.md`. 요지 셋.

### ① 통제어휘 이탈률 0.00% — **판별력이 없다**

enum 이 디코딩에서 강제되므로 **목록 밖 값은 생성 자체가 불가능**하다. Opus 쪽도
같은 상태였다. **0%는 gemma 의 어휘 준수가 아니라 디코더가 어기게 놔두지 않았다는
사실을 잰 값이다.** 사전 등록 §2.1-2 가 걱정한 것이 실제로 일어난 사례로 기록했다.
**합격/불합격은 실질적으로 ②가 갈랐다.**

측정은 사전 등록이 지정한 판정기로 했다 — MARA `contract_import.validate_record`
**위반 0건**, 생산자 `check_10_vocab` PASS. **새 판정기를 만들지 않았다.**

### ② structured output 실패율 0.00% — **기준선은 가정이다**

30건 전부 1회에 통과(재시도 0, 절단 0). 그런데 Opus 기준선은 **"기록이 없다 →
0건으로 본다"** 이고, 사전 등록 자신이 *"기록이 없다와 0이었다는 다르다"* 고 경고하며
양쪽 모두 카운터를 남기라고 했다. **한쪽만 남겼다.** Opus 실행은 지나갔고 다시
돌리는 것은 벤더 호출이라 **해소 불가**다.

실패는 세 갈래로 나눠 적는다 — **문법 밖(구조상 불가능) / 수량 제약 위반(모델) /
절단(`max_tokens`)**. 섞으면 수치가 모델이 아닌 것을 잰다.

### ③ judge — **측정하지 않았다**

자기 선호 편향은 알던 문제다. **결정적인 것은 Opus 측 골든셋 예측이 레포에 없어
"차이"를 계산할 수 없다는 것이다.** 골든셋 3건의 URL 은 재추출 30건 어디에도 없고
`eval/scores/` 는 비어 있다. **비교 대상 없는 절대값은 참고값도 되지 못하므로**
호출 자체를 하지 않았다.

> **`eval.judge_model` 자체는 이전했다.** 측정을 안 한 것과 벤더를 계속 가리키는
> 것은 다르다 — 후자는 전제 위반이다.

### 합격선 밖 관찰 (판정에 넣지 않음)

발표유형 일치 **26/30**, 기술영역 집합 완전일치 **10/30**(단 30/30 이 1개 이상 겹침),
영향도 동일 **21/30**(MAE 0.30), 요약 길이 중앙 186자→**129자**, `관련기존기술`
개수 1.9→**0.9개**(`LVLM` 같은 약어 — D-020 "영어 표준형"이 약하게 지켜진다).
요약 문체 규칙 위반 **0건**. 지연 17.0초→**3.4초**, 비용 **$0**.

## 주의 (이월, 여전히 유효)

- 테스트는 가상환경으로: `.venv/Scripts/python.exe -m pytest tests/ -q`.
- **실제 Obsidian Vault 에 절대 쓰지 않는다.** 관측 로그·보존소·`data/replays/` 도 같다.
- **다른 레포를 테스트 입력으로 읽지 않는다.** 이번에 MARA `contract_import.py` 를
  **측정에** 썼지만 일회성 스크립트이고 **레포 코드·테스트에 의존성을 만들지 않았다.**
- 셸 스크립트는 **LF 로 체크아웃되어야 한다** (`.gitattributes`).
- 실행에 쓰인 프롬프트 버전은 **수정하지 않는다.** 새 버전 파일을 만든다.
- 문서·규칙에 벤더 호출 표현을 쓸 때는 **Write/Edit 도구**로 쓴다. 명령줄에 넣으면
  훅이 그 명령 자체를 차단한다 (이번 세션에서도 한 번 걸렸다).
- **push 전에** `git log --oneline` 으로 확인한다.

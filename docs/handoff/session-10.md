## 3. 🚩 재발 방지 — 테스트를 **추가했다** (D-079)

권고했던 이유는 최근 세 세션이 전부 같은 모양이었기 때문이다 — F1 롤백, 트립와이어
범위, D-052 순서. **문서·주석이 선언한 것과 실제가 달랐고, 셋 다 테스트를 쓰다가
드러났다.** 결정 로그만 선언으로 남겨 둘 이유가 없었다.

`tests/test_decision_log.py` 가 재는 것 5가지:

| 검사 | 잡는 것 |
|---|---|
| 번호 중복 | **F9 그 자체** |
| D-001 부터 연속 | 행을 지웠거나(governance 금지) 번호를 건너뛴 경우 |
| 상태어가 닫힌 집합 | `유효`/`번복됨`/`부분 번복` 밖의 상태어 (뒤에 붙는 사유는 자유) |
| 번복 행이 대체 결정을 가리킴 | 상태만 내려 두고 후속 결정을 안 적은 경우 |
| 참조가 실재하는 결정을 가리킴 | 번호가 한 자리 틀려 끊어진 참조 |

### 이 테스트가 보장하지 **않는** 것

- **내용이 아니라 구조만 잰다.** 근거가 참인지, 상태가 실제 코드와 맞는지는 알 수 없다.
  `test_vocab_sync.py` 가 어휘 미러에 대해 하는 일과 같은 층위다. 그 판단은 여전히 사람 몫이다.
- **대가가 하나 있다: 결정 로그 표 안에 예시용 가짜 D 번호를 쓸 수 없다.** 실제로
  D-079 를 쓰면서 걸렸다 — 오타 예시로 적은 번호를 참조 검사가 끊어진 참조로 읽었다.
  **테스트에 예외를 두는 대신 문장에서 가짜 번호를 뺐다.** 예외를 두면 정확히 오타가
  그 구멍으로 빠져나간다.
- **ADR 번호(`docs/adr/`)는 재지 않는다.** 같은 모양의 검사가 가능하지만 이번 범위가
  아니었다. 해 볼 만한 다음 항목이다 (§6).

- **push 전에** `git log --oneline` 으로 확인한다.

## 2. F5 를 닫는다 — 무엇으로 닫았는가

session-08 §6 이 남긴 목록이 그대로 할 일이었다. 전부 덮었다.

| session-08 이 적은 미검증 항목 | 이번 세션 |
|---|---|
| `run()` — 보존소 순회, `--limit`, 매 건 누적본 갱신 | ✅ 15건 |
| **`raw/` 선기록 (D-052)** | ✅ 6건 — **여기서 결함이 나왔다** (§3) |
| `_write_json` 원자적 쓰기 | ✅ 8건 |
| `raw_item_from_stored` — "한 글자도 손보지 않는다" | ✅ 8건 |
| (목록에 없던 것) **CLI** — 명령줄 → `run()` 인자 | ✅ 3건 |

CLI 를 같이 넣은 이유는 **실행이 언제나 명령줄에서 시작하기 때문**이다. 위 네 묶음이
전부 초록불이어도 `--out` 이 `store_dir` 로 이어져 있으면 실제 실행은 다른 것을 한다.
변이 검사에서 그 오배선은 2건을 깬다 (§8).

### ⚠️ 이 테스트가 보장하지 **않는** 것

- **원자성 자체를 증명하지 않는다.** `os.replace` 가 이 파일시스템에서 원자적이라는
  것은 플랫폼의 성질이고 테스트가 만들 수 있는 사실이 아니다. 잴 수 있는 것은
  **관측 가능한 결과**뿐이다 — 실패한 쓰기가 부분 파일도 임시 파일도 남기지 않는가,
  실패해도 **이전 파일이 그대로인가**. 임시 파일이 **대상과 같은 디렉터리**에
  만들어지는지도 함께 못 박았다(다른 파일시스템이면 `replace` 가 원자적이지 않다).
- **엔드포인트의 강제(ADR-019)는 여전히 여기서 확인되지 않는다.** 전부 `transport`
  주입이다. 서버의 성질은 실제 호출로만 확인되고, 절차는 `.claude/rules/vllm-endpoint.md`
  에 있다.
- **기존 `data/replays/{main,sample}` 을 다시 돌리지 않았다.** 한 바이트도 쓰지 않았다.

## 3. 🚩 테스트가 잡은 것 — D-052 는 있었고, **위치가 틀렸다**

`raw/` 선기록을 검사하려고 쓴 테스트가 빨개졌다. 코드는 이랬다.

```python
try:
    result = client.parse_into(...)
except ...:
    row |= {...}
else:
    row |= {"ontology": ontology.model_dump(...)}   # ← 변환

# --- 원본을 먼저 내린다 (D-052) ---   ← 주석은 맞고 위치가 틀렸다
```

**주석에는 "원본을 먼저 내린다"라고 적혀 있었다.** 실제로는 행을 다 만든 **뒤**에
내리고 있어서, 성공 경로에서 변환이 터지면 응답이 통째로 사라진다. 잃는 것은 돈이
아니라 **같은 입력에 대한 그 모델의 응답**이고, 다시 불러 받은 것은 그 응답이 아니다.

`_persist_raw` 로 떼어 `parse_into` 를 감싼 **`finally`** 에서 부른다 (D-077).
이제 성공·격리·전송 실패·인터럽트 **어느 경로로 나가든 응답이 있으면 디스크에 있다.**

> **드러난 경위가 ADR-017 · F11 · F12 와 같은 모양이다.** 장치(규칙·주석)는 있었고,
> **그것이 맞는지 확인하는 것이 없었다.** session-08 의 `127.` 접두사 구멍도
> 변이 검사가 아니라 **테스트를 쓰다가** 나왔다 — 같은 경로다.

## 5. 설계 판단 — 왜 ADR 이 아닌가

session-06 · 07 · 08 과 같은 계산이다. **새 의존성 0개, 외부 서비스 선택 아님,
MARA 가 읽는 출력 계약(JSONL·manifest) 불변.**

걸릴 만한 것은 `rows.json` 의 **키 순서**가 바뀐다는 것 하나다(`finish_reasons` 가
`ok`·`failure` 보다 앞에 온다). 이 파일은 계약 산출물이 아니라 이 레포 안의 측정
기록이고 MARA 가 읽지 않는다. 값은 하나도 바뀌지 않는다. D-077 · D-078 로 남겼다.
**다른 판단이었으면 `adr-skill:adr-recorder` 로 갔어야 한다** (F12).

- **테스트 파일을 합치지 않았다.** 집계 쪽은 행 딕셔너리만 있으면 되고, 실행 쪽은
  보존소·transport·파일시스템이 다 필요하다. 목이 다른 것을 한 파일에 두면 무엇이
  깨졌을 때 **어느 층이 깨진 것인지** 먼저 읽어야 한다.
- **`raw_item_from_stored` 의 URL 정규화를 없애지 않았다.** `HttpUrl` 은 호스트를
  소문자로 만들고 빈 경로에 `/` 를 붙인다. 보존소 값은 **이미 `RawItem` 을 거쳐 나온
  값이라 고정점**이고(테스트로 고정), 손으로 고친 값만 바뀐다. 파싱을 빼면 타입이
  무너지고, 얻는 것은 "보존소를 손으로 고쳐도 된다"는 잘못된 신호뿐이다.
- **`replay_one` 의 실패 삼킴을 그대로 뒀다.** 한 건이 터졌다고 멈추면 실패율 자체를
  셀 수 없다 (사전 등록 §3②). 대신 **삼키지 않는 종류**(`KeyboardInterrupt`)로
  죽였을 때 거기까지가 디스크에 남는지를 테스트로 못 박았다.

- 셸 스크립트는 **LF** 로 유지한다. CRLF 면 훅이 조용히 안 돈다.
- **push 전에** `git log --oneline` 으로 확인한다.

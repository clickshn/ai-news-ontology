## 4. 🔒 단계와 판정

### 4.1 단계 F — 형식 확인 소표본 (v6 × 3항목 × 1회)

| 🔒 통과 기준 (3건 **전부**) | 하나라도 어기면 |
|---|---|
| judge 성공 (스키마 통과) | **멈춘다.** 본 실행으로 가지 않는다 |
| `stop_kind == "stop"` (재시도 없음) | 퇴화면 한 줄 형식만으로는 부족하다는 뜻 — 원본을 보고 보고한다 |
| 요소 판정 파싱 성공 (`completeness_scored_by == "code"`) | 원본 근거를 보고 **파서인지 형식 지시인지** 먼저 가린다 (D-051 전례) |

**통과해도 본 실행은 별도 승인을 받는다.** 소표본 결과는 본 실행 통계에 합치지 않는다.

### 4.2 본 실행 (v6 × 3항목 × 10회 = 30)

| 가설 | 무엇을 보나 | 🔒 통과 기준 | 실패하면 |
|---|---|---|---|
| **H0 대조군 재현** (전제) | v3 완결성 최빈값 | 4 / 5 / 4 | 환경 변화 의심. v6 는 그대로 돌리되 비교는 같은 날 v3 하고만 |
| **H1 형식** | 항목별 파싱 성공률 = (10 − `element_parse_failures`) / 10, `length_stops` | **3항목 모두 ≥ 0.9** ∧ 퇴화 0 | 파서 먼저 의심(원본 재집계, 호출 0) → 형식 지시 |
| **H2 결정성** | 코드 계산 완결성 `mode_ratio`, `spread` | **3항목 모두 mode_ratio ≥ 0.9 ∧ spread ≤ 1** | `element_verdict_counts` 로 흔들린 요소를 특정 |
| **H3 요소 경로** | 요소별 최빈 판정 vs §2 손계산 | 19요소 중 **≥ 18 일치** (기록) | 갈린 요소의 근거를 인용해 기록. 라벨·손계산을 사후에 고치지 않는다 |
| **H4 중심** | 코드 계산 최빈값 vs 손계산 3 / 3 / 3 | 기록만. 3/3 = 수렴, 2/3 = 부분 수렴 | H3 로 원인 요소를 찾는다 |

**기본 루브릭 전환 조건: H1 ∧ H2.** H3·H4 는 전환 조건이 아니다 — 손계산은 에이전트의 것이고
judge 와 갈려도 어느 쪽이 틀렸는지를 말하지 않는다 (v4 사전 등록과 같은 원칙).

> **전환 조건이 v5 보다 약해 보이는 이유.** v5 의 H1·H5 가 재던 것이 v6 에서 구조상 보장된다.
> 남는 위험은 요소 판정의 **체계적 기울기**(설계 문서 §4)인데, 그것은 반복 채점으로 드러나지
> 않는다 — 10/10 같은 모양으로 기울면 H2 는 통과한다. **그래서 조건이 충족돼도 기본값 전환은
> 결과 보고 후 사람이 확인하고 적용한다** (ADR-021 을 Accepted 로 올리는 것을 동반한다).
> 조건은 지금 고정하고, 적용 여부만 사람 몫으로 둔다.

### 판정 밖 관찰 (기록만)

- **O1 요소 판정이 v5 에서 옮겼는가.** v6 는 슬롯 판정어·점수표를 judge 에게 보이지 않는다. 19요소
  중 v5 최빈 판정과 같은 수를 센다. 특히 **#33001 ②(a)** 가 여전히 `이름만` 인지 — 점수표가 판정을
  끌고 있었다면 여기서 움직인다.
- **O2 다른 축 누수.** 충실성·간결성이 v5(30/30 5점)와 달라지는가. 본문은 같지만 출력 스키마가
  다르다(완결성 score 칸 없음).
- **O3 근거 길이.** 출력 토큰(v5 호출당 ≈216) — 판정어·합계를 빼면 줄어야 한다.

## 5. 🔴 답하지 못하는 것

v4 · v5 사전 등록 §4 그대로 (정확도 · 자기 편향 · 분모 제외 경로 · 일반화 · 라벨 초안의 영향). 추가로:

- **요소 판정의 체계적 기울기.** 반복 채점은 흔들림을 재지 기울기를 재지 않는다. #33001 ②(a) 는
  라벨(복합 요소 가능성)과 판정 기준 중 어느 쪽 문제인지 이 실행이 가르지 않는다 — 라벨 수정은 사람의 몫.
- **v6 점수와 v5 이하 점수의 비교.** 뜻이 다르다 (ADR-021). 비교하지 않는다.

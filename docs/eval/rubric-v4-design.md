## 1. 무엇을 고치나 — 층이 다른 결함 두 개

| | 결함 | 처음 드러난 곳 | 층 |
|---|---|---|---|
| A | **분모 결정 규칙이 없다.** "원문이 주지 않은 슬롯은 분모에서 뺀다"(D-053)를 언제 적용하는지 v3 에 없다 | session-12 S3Gym — 같은 요약에 3/4(4점) 4회, 3/3(5점) 1회 (D-088) | 분모 |
| B | **부분 충족을 표현할 칸이 없다.** 요소 일부만 담은 슬롯이 충족/미충족 둘 중 하나로 밀린다 | 골든셋 3건 실행 #33003 ④ — 사람은 부분(→미충족), judge 는 충족 (D-060) | 슬롯 하나의 판정 단위 |

**같이 고친다.** 따로 고치면 v3 검증 결과(D-048)와의 단절을 두 번 낸다 (D-055 와 같은
계산). 그리고 둘은 **같은 뿌리**를 가진다 — 슬롯마다 "원문이 준 핵심 요소가 무엇인가"가
고정돼 있지 않다. 그것이 고정돼 있으면:

- A: 요소가 0개인 슬롯 = 원문이 주지 않은 슬롯. 분모는 세면 된다.
- B: 요소 일부만 담김 = 부분. "일부"가 관측 가능한 판정이 된다.

### session-12 기준선에서 B 가 늘었는가

늘었다. 사례가 #33003 1건(D-060)에서 **3건 전부**가 됐다. 다만 v3 에는 그것을 적을
칸이 없어서 **전부 충족으로 기록됐다** — 점수에는 흔적이 없다.

| 항목 | v3 기준선 | v3 judge 가 "충족"으로 적은 부분 충족 |
|---|---|---|
| #33001 | 4.0 (5/5) | ③정도 — 원문은 "Medium 등급·메모리 손상 없음·DoS", 요약은 "DoS" 만 |
| #33003 | 5.0 (5/5) | ④경위 — 원문은 위반 이력 + 지배권 변경 해지 조항, 요약은 위반 이력만 (D-060 과 같은 자리) |
| S3Gym | 4.2 (4–5) | ③정도 — 4회차 근거가 직접 "충족 - 구체적 수치는 없으나 결과의 경향성을 언급함" |

S3Gym 의 ③ 은 A 와 B 가 **한 슬롯에서 겹친** 경우다. 4회는 "경향만 있다"를 충족으로,
1회는 "수치가 없다"를 원문 미제공(분모 제외)으로 읽었다. **사람은 원문이 ③을 줬다고
봤다** (2026-09-01 라벨 notes: "세 경로 조건부 우열과 부정 전이").

## 2. 판정 주체 — 누가 "원문이 주지 않았다"를 정하나

| 안 | 판정 주체 | 비결정성 | 기각 사유 |
|---|---|---|---|
| (1) v3 에 판정 기준을 더 적는다 | 채점 호출 안의 judge | **남는다** | 기준을 아무리 적어도 판단은 매 회차 다시 샘플링된다. 줄일 수는 있어도 없앨 수 없다 |
| (2) 원문만 보는 별도 호출로 분모를 먼저 정하고 캐시한다 | 별도 호출의 judge | **굳는다** | 분모 판단이 슬롯 판정을 끌고 가던 결합(D-088: ③ 제외와 ④ 충족이 같이 움직임)은 끊지만, 흔들리는 판단 **하나를 뽑아 고정**할 뿐이다. 어떤 샘플이 뽑혔는지가 이후 모든 점수를 정한다 |
| (3) 사람이 슬롯별 분모만 라벨한다 | 사람 | 분모는 없다 | B 가 남는다. 요소가 무엇인지 모르면 "일부"를 judge 가 다시 판단한다 |
| **(4) 사람이 슬롯별 핵심 요소를 라벨한다** | **사람** | **분모·요소 선택 모두 없다** | **채택** |

(4) 가 성립하는 전제는 **judge 가 골든셋에만 돈다**는 것이다 — `build_judge_variables`
가 `GoldenItem` 을 받는다. 라벨 없는 코퍼스 항목을 채점하는 경로는 없다. 그 경로가
생기면 이 설계는 그 경로에 적용되지 않고, 따로 정해야 한다.

## 3. 설계

### 라벨 — `completeness_slots`

```json
"completeness_slots": {
  "사건": ["..."],
  "범위": ["..."],
  "정도": ["...", "..."],
  "경위": []
}
```

- **빈 목록 = 원문이 그 슬롯을 주지 않았다 = 분모 제외.** 네 키는 모두 필수다.
- ①사건은 비울 수 없다. 슬롯당 최대 3개, 같은 요소를 두 슬롯에 넣지 않는다.
- 라벨링 가이드는 `eval/golden_set/README.md` "완결성 슬롯 라벨링".

### judge 가 하는 일

1. 요소마다 **담김 / 이름만 / 없음**. 이름만은 담김이 아니다 (D-045 규칙을 요소 단위로).
2. 슬롯 판정은 요소 판정에서 기계적으로: 전부 담김 = **충족 1**, 일부 = **부분 0.5**,
   하나도 없음 = **미충족 0**, 빈 목록 = **분모 제외**.
3. 점수는 고정 표 — r = 합계 / 분모. ①미충족이면 1, r=1 → 5, ≥0.75 → 4, ≥0.5 → 3,
   그 밖 → 2. 분모 4·정수 합계에서는 v3 구간과 같다. v3 의 "2/3 ≈ 3~4" 같은 범위는 없앴다.
4. 근거 형식 고정 — 슬롯마다 판정어를 콜론 바로 뒤에, 마지막 줄에 `→ 합계 x / 분모 n →
   점수 s`.

### 과정 검사 — 점수와 독립적으로 (D-051 과 같은 원리)

| 지표 | 무엇을 보나 | 낮으면 |
|---|---|---|
| `denominator_adherence` | 근거의 분모 = 라벨 분모인 회차 비율. **v3 회차에도 잰다** | judge 가 라벨을 무시하고 분모를 다시 정했다 |
| `state_adherence` | 4슬롯 모두 판정어가 읽힌 회차 비율 | 형식을 안 따랐다 (또는 파서가 틀렸다 — D-051 의 전례) |
| `score_table_adherence` | judge 점수 = 자기 판정에 점수표를 적용한 값인 회차 비율 | 판정은 했는데 **표를 적용하지 않았다** |

`slot_adherence`·`slot_fill_rate` 는 **v3 의미 그대로 뒀다.** 바꾸면 session-12 까지의
기록을 재집계했을 때 다른 값이 나온다. 대신 4상태 파서(`slot_states`)를 따로 두었다 —
`slot_verdicts` 는 "부분 충족"을 부분 문자열 때문에 충족으로 읽는다.

**파서를 저장된 session-12 근거에 먼저 돌렸다** (호출 0건). S3Gym 0회차만 분모 3,
나머지 14회는 4. 판정이 다 읽힌 14회 전부에서 judge 점수 = 표 적용값. D-088 의 관찰이
숫자로 재현된다 (`tests/test_eval_rubric_v4.py::test_session12_denominator_drift_is_visible`).

### judge 출력 스키마는 바꾸지 않았다

슬롯 판정을 `SummaryJudgement` 의 필드로 받으면 파싱이 훨씬 견고해진다. 그러나 그
스키마는 structured output 으로 **v3 대조군에도 그대로 들어간다** — 바꾸면 v3 대조군이
session-12 와 다른 디코딩 제약에서 돌고, 대조군이 대조군이 아니게 된다. 텍스트 형식을
고정하고 파서로 읽는다.

### 그 밖에 v4 에서 바뀐 것

- v3 의 #33001 경계 사례를 **가상 예시로 바꿨다.** 채점 대상 항목의 판정이 루브릭에
  들어 있으면 그 항목은 정답지를 보고 채점된다. v3 은 #33001 을 채점하면서 #33001 의
  판정 예시를 들고 있었다.
- "AI 뉴스" → "AI 관련 뉴스·논문" (D-055 가 v4 로 미뤄 둔 정정).
- 충실성·간결성 본문은 **글자 그대로 같다** (테스트로 고정).

## 4. 🔴 대가

### 4.1 골든셋 라벨링 비용이 늘어난다

항목당 **슬롯 4개 × 요소 n개**를 사람이 확정해야 한다. 이번 3건은 항목당 요소 5~7개였고,
요소마다 **원문의 어느 줄이 근거인지** 확인해야 했다 — 초안만 보고 정하면 원문에 무엇이
있었는지를 초안이 대신 판단한 게 된다 (session-13 에서 원문 전체를 다시 펼친 이유).

- 골든셋 증가 속도가 원래 느리다 (경계 사례 위주, D-039). 여기에 비용이 하나 더 붙는다.
  **쉬운 항목으로 건수를 채우고 싶은 압력이 커진다** — 그 압력이 D-039 가 막는 방향이다.
- 기존 항목은 **라벨을 소급해야 v4 로 채점된다.** 3건은 이번에 소급했다.
- 요소 경계는 판단이다. 원자 요소로 쪼개는 방식에 따라 부분/충족이 갈린다 (§5).

### 4.2 judge 가 재는 것이 바뀐다 — 의도한 축소다

| | v3 | v4 |
|---|---|---|
| judge 의 일 | **무엇이 핵심인지 판단**하고, 그것이 요약에 있는지 본다 | **주어진 요소가 요약에 있는지 확인**한다 |
| 핵심을 정하는 주체 | judge (매 회차) | 사람 (라벨 확정 시 1회) |
| 점수의 뜻 | 요약의 완결성에 대한 judge 의 판단 | **라벨 대비 커버리지** |

**왜 좁히나.**

1. **비결정성의 출처가 앞의 판단이었다.** session-12 의 흔들림은 요소가 요약에 있는지가
   아니라 **무엇을 셀지**(분모)에서 났다. 셀 대상을 고정하는 것이 D-045 의 방향이었고
   ("셀 대상을 먼저 고정"), v4 는 그 방향을 슬롯 이름에서 **슬롯 내용**까지 한 칸 더
   민 것이다.
2. **그 판단은 원래 골든셋의 몫이다.** 골든셋은 "사람이 확정한 정답"이다 (D-039).
   "이 기사의 핵심이 무엇인가"는 정답의 일부이고, 그걸 judge 가 매번 정하면 정답의
   일부를 모델이 쓰는 것이다.
3. **자기 선호 편향이 가장 크게 들어가는 자리를 치운다.** judge 와 추출이 같은 모델이다
   (D-088). "무엇이 핵심인가"를 judge 가 정하면, 요약을 쓴 모델이 무엇을 핵심으로
   봤는지와 같은 방향으로 기울 여지가 가장 크다. "주어진 요소가 있는가"는 그 여지가
   작다. **없어지지는 않는다** — "담김"과 "이름만"의 경계는 여전히 judge 가 긋는다.

**잃는 것.**

- **라벨에 없는 핵심을 요약이 담아도 점수가 오르지 않는다.** 라벨이 핵심을 놓치면
  그 요약은 부당하게 낮게 나온다.
- **라벨이 틀리면 judge 는 틀린 기준을 일관되게 적용한다.** 비결정성이 줄어드는 만큼
  라벨 오류가 **결정적으로** 점수에 박힌다 — 흔들림이 없으니 눈에 덜 띈다.
- **v3 점수와 같은 구성개념이 아니다.** v3 4.0 → v4 3.0 을 "요약이 나빠졌다"로 읽지
  않는다. 잣대가 바뀐 것이다. 추이는 v4 기준선부터 다시 센다.

## 5. 경계 판단 — 사람이 정한 것 (session-13)

라벨은 사람이 원문 전체를 읽고 확정했다. 판단이 갈릴 수 있었던 자리와 그 근거를
**사람의 말 그대로** 남긴다 — 다음 라벨링의 기준이 이것이다.

### S3Gym ③정도 — 정성적 크기·방향도 "정도"다

원문(초록)에는 수치가 하나도 없다. "neither automatic nor uniform", "depends strongly",
"substantial gains", "unstable improvement", "severe negative transfer" 만 있다.

- **판단: (가) 정성적 표현도 정도로 본다.** ③은 원문이 **제공한** 슬롯이다.
- (나)(수치·등급만)를 택하면 논문 초록 대부분에서 ③이 구조적으로 빠진다.
- 이 요약에서는 어느 쪽이든 점수가 같았다(2.5/4 와 2/3 모두 3). 그래서 이 판단은
  한 건의 점수가 아니라 **앞으로 논문 항목에서 ③을 어떻게 세는가**를 정한 것이다.
- session-12 의 5점 회차가 바로 (나)로 읽은 경우였다. v4 에서는 이 판단을 judge 가 하지 않는다.

### #33001 "21바이트 재현" — 어느 슬롯에도 넣지 않는다

원문에서 "21바이트"는 네 자리에 나온다: 도입 요약(1줄), 자체 소제목 "21바이트 재현
입력"(19–22줄), "영향과 악용 가능성" 소제목(35줄), 회귀 테스트(48줄).

> 원문이 "발견 과정" 소제목에 포함시키지 않았고, 35줄의 무게는 36줄 "얕은 트리거
> 경로"로 이어진다. **여러 슬롯에 걸쳐 읽히는 것 자체가 원자 요소가 아니라는 신호다.**
> — 사람의 판단 (session-13)

이것이 라벨링 가이드의 규칙이 됐다: **두 슬롯 이상으로 읽히는 정보는 요소로 쓰지
않는다** — 그 정보를 어느 슬롯에 넣을지가 점수를 가르는데(④에 넣으면 이 항목이 3 → 4),
그 선택의 근거가 원문에 없다.

### #33003 ④(b) 지배권 변경 해지 조항

원문 20줄의 조항은 "판단 근거" 소제목(7–16줄) 밖, "향후 모델 공급과 개발자 전환"
아래에 있다. **판단: 요소로 유지한다** — ④ = (a) 위반 이력 / (b) 해지 조항.

> 20줄이 "판단 근거" 소제목 밖에 있는 건 맞지만, 사람이 2026-09-01에 이 조항의
> 누락을 ④ 부분 충족 사유로 판단한 기록(D-060)이 더 무겁다. **골든셋 라벨은 사람
> 판단의 기록이고, 소제목 위치는 그 판단을 뒤집을 근거가 아니다.** 또한 v4를 만든
> 이유가 D-060의 "부분 충족 표현 불가"인데 그 사례의 근거를 빼면 v4가 표현하려던
> 케이스 자체가 없어진다. — 사람의 판단 (session-13)

**#33001 의 판단과 비대칭으로 보이지만 층이 다르다.** 21바이트는 "원문 구조상 여러
슬롯에 걸친다"를 근거로 뺐고, 해지 조항은 "원문 구조보다 기록된 사람 판단이 무겁다"를
근거로 남겼다. 앞의 것은 **요소가 원자인가**의 문제고, 뒤의 것은 **원자 요소가 어느
슬롯인가**의 문제다 — 해지 조항은 ④ 말고 다른 슬롯으로 읽히지 않는다.

Astra 안전 책임 증가(21줄)는 **넣지 않았다.** 넣어도 점수가 같고(④ 부분) 라벨링
비용만 는다. 같은 형태의 경위가 반복되면 그때 추가한다 (`eval/golden_set/README.md`
"관찰 필요").

## 6. 한계

- **실제 골든셋에서 "분모 제외" 경로가 한 번도 쓰이지 않는다.** 3건 모두 사람 기준으로
  4슬롯을 전부 제공했다. 분모 제외는 단위 테스트로만 검증된다 — 원문이 잘린 소스(D-013)
  항목이 골든셋에 들어올 때 처음 실제로 쓰인다.
- **`judge_human_gap` 은 여전히 무효다** (D-087). 사람 점수는 v3 기준, Opus 요약에 매긴
  것이다. v4 라벨은 **원문에 대한** 판단이라 요약에 매이지 않지만, 사람 점수는 그렇지 않다.
- **"담김"과 "이름만"의 경계는 judge 가 긋는다.** 비결정성이 남는다면 여기다. 검증에서
  슬롯별 판정 도수(`slot_state_counts`)로 본다.

## 3. 🔒 가설과 판정 기준 — 데이터 보기 전에 고정

**손계산 예상치** (라벨 확정 시 사람에게 제시한 것 그대로, `rubric-v4-design.md` §5):

| 항목 | ①사건 | ②범위 | ③정도 | ④경위 | 합계 | v4 예상 | v3 기준선 (session-12) |
|---|---|---|---|---|---|---|---|
| #33001 | 충족 | 충족 | **부분** (DoS 만) | 미충족 | 2.5/4 | **3** | `{4:5}` |
| #33003 | 충족 | **미충족** (개발자 없음) | 충족 | **부분** (위반 이력만) | 2.5/4 | **3** | `{5:5}` |
| S3Gym | 충족 | 충족 | **부분** (경로별 차이만) | 미충족 (경로는 이름만) | 2.5/4 | **3** | `{4:4, 5:1}` |

> 이 예상치는 **에이전트가 요약을 읽고 계산한 것**이고, 사람은 그 계산을 보고 라벨을
> 확정했다. 예상과 judge 가 갈려도 **어느 쪽이 옳은지를 이 실행이 가르지 않는다** — 갈린
> 슬롯과 요소를 기록할 뿐이다 (H4).

| 가설 | 무엇을 보나 | 🔒 통과 기준 (팔 A) | 실패하면 |
|---|---|---|---|
| **H0 대조군 재현** (전제 검사) | B 의 완결성 최빈값이 session-12 와 같은가 | 3항목 모두 최빈값 일치 (4 / 5 / 4) | **환경 변화 의심.** A 는 그대로 돌리되, v3 과의 비교는 **같은 날의 B 하고만** 한다. session-12 수치와 A 를 직접 비교하지 않는다 |
| **H1 분모 고정** | `denominator_adherence` | **3항목 모두 ≥ 0.9** (각 10회 중 9회 이상 분모 4) | judge 가 라벨을 무시하고 분모를 다시 정한다 = **v4 의 핵심 전제가 깨졌다.** 기본 루브릭을 바꾸지 않는다 |
| **H2 완결성 결정성** | 완결성 `mode_ratio`, `spread` | **3항목 모두 mode_ratio ≥ 0.9 ∧ spread ≤ 1** | 분모를 고정해도 흔들린다 → 남은 원인을 `slot_state_counts` 로 특정한다("담김/이름만" 경계가 후보) |
| **H3 중심 = 손계산** | A 의 완결성 최빈값 | 항목별로 기록. **3/3 일치 = 수렴, 2/3 = 부분 수렴, 그 이하 = 불일치** | 불일치 슬롯을 H4 로 찾는다. 라벨·예상을 사후에 고치지 않는다 |
| **H4 판정 경로 일치** | 슬롯별 최빈 판정 vs 위 표 | **12슬롯 중 ≥ 11 일치** | 갈린 슬롯의 근거를 인용해 기록. D-048 이 본 것은 점수가 아니라 **판정 경로의 일치**였다 |
| **H5 과정 준수** | `state_adherence`, `score_table_adherence` | **3항목 모두 둘 다 ≥ 0.9** | 형식을 안 따랐거나(→ 파서부터 의심, D-051 전례) 표를 적용하지 않았다 |
| **H6 흔들림 감소** | `sd(A)` vs `sd(B)` | 항목별로, **B 의 spread > 0 인 항목에서만** 판정: `sd(A) < sd(B)` | **B 가 그 항목에서 흔들리지 않았으면 "판정 불가"** 로 적는다 — D-048 의 H2 가 그랬다(줄일 흔들림이 없었다). 기각으로 읽지 않는다 |

### 기본 루브릭을 v4 로 바꾸는 조건

**H1 ∧ H2 ∧ H5 전부 통과**일 때만 `DEFAULT_JUDGE_PROMPT` 를 v4 로 올린다. H3·H4 는 전환
조건이 아니다 — 에이전트의 손계산과 judge 가 갈렸다는 것은 **어느 쪽이 틀렸는지를
말하지 않는다.** 하나라도 실패하면 기본값은 v3 으로 두고 실패 지점을 handoff 결정
대기로 넘긴다.

### 판정 밖 관찰 (기록만)

- **O1 다른 축 누수.** v4 의 충실성·간결성 본문은 v3 과 글자 그대로 같다. 그래도 A 에서
  두 축이 session-12(전부 5.0, sd 0)와 달라지면, 완결성 절의 변화가 **문맥으로 다른 축에
  번졌다**는 신호다. 가설로 두지 않는 이유: 본문이 같아도 프롬프트 전체 길이·예시가 달라
  "같은 조건"이 아니다.
- **O2 v3 에서 분모 준수.** B 의 `denominator_adherence` 를 라벨(4) 기준으로 기록한다.
  session-12 는 S3Gym 0.8 이었다.
- **O3 v3 의 "부분 충족 → 충족" 기록.** B 근거에서 부분 충족을 충족으로 적은 슬롯을 센다
  (`rubric-v4-design.md` §1 표의 세 자리).

## 4. 🔴 이 실행이 답하지 못하는 것

- **v4 점수가 "맞는지".** 사람 점수(`human_summary_scores`)는 v3 기준으로 **Opus 요약에**
  매긴 것이라 이번 요약과 비교할 수 없다 (D-087). 이 실행은 **재현성과 규칙 준수**를 재지
  정확도를 재지 않는다.
- **자기 선호 편향.** judge 와 추출이 같은 모델이다. v4 는 편향이 들어갈 자리를 줄였지만
  (핵심 판단을 사람에게 넘겼다) 재지는 않는다.
- **"분모 제외" 경로.** 세 항목 모두 분모 4 라 실제로 쓰이지 않는다. 단위 테스트로만
  검증된다.
- **일반화.** 3건이다. 필드 하나의 레버리지가 큰 표본이다 (session-12 §5).
- **라벨 초안의 영향.** 라벨은 사람이 원문을 읽고 확정했지만 **초안은 에이전트가 썼다.**
  초안이 사람의 판단을 끌었는지는 이 실행이 가를 수 없다.

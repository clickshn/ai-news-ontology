## 3. 🔒 단계와 판정

### 3.1 단계 F — 형식 확인 소표본 (v5 × 3항목 × 1회)

"규모가 큰 호출은 단계로 쪼갠다"(`docs/governance.md`)의 적용이다. **v4 가 정확히 이 원칙이
막으려던 경우였다** — 30건 본 실행 전에 형식을 확인했다면 형식 결함을 1~3건에서 잡았다.

| 🔒 통과 기준 (3건 **전부**) | 하나라도 어기면 |
|---|---|
| judge 성공 (스키마 통과) | **멈춘다.** 본 실행으로 가지 않는다 |
| `stop_kind == "stop"` (재시도 없음) | 퇴화면 v5 형식 가설이 **기각** — 원인이 형식 지시가 아니다 |
| `state_adherence == 1` (4슬롯 판정어가 전부 읽힘) | 파서부터 의심한다 (D-051 전례) |
| 근거의 분모 = 4 | H1 의 전조 |

**통과해도 본 실행은 별도 승인을 받는다** (governance: "결과를 보여준 뒤 본 실행은 별도
승인"). 소표본 결과는 본 실행 통계에 **합치지 않는다** — 형식 확인용이다.

### 3.2 본 실행 (v5 × 3항목 × 10회 = 30)

가설 **H1~H5 는 v4 사전 등록 §3 과 같다** — 분모 준수 ≥ 0.9, 완결성 mode_ratio ≥ 0.9 ∧
spread ≤ 1, 중심 = 손계산(3 / 3 / 3), 판정 경로 12슬롯 중 ≥ 11 일치, 과정 준수 ≥ 0.9.
손계산 예상치도 같다 (라벨·요약이 그대로다).

기본 루브릭 전환 조건도 같다: **H1 ∧ H2 ∧ H5.**

### 3.3 새로 기록하는 것 — 실패 갈래 (D-093)

본 실행의 실패는 `length_stops` 로 **절단 / 퇴화 / 구분 불가**를 따로 센다. 처방이 정반대라
합쳐 적지 않는다 — 절단이면 `max_tokens` 가 유효하고, 퇴화면 무효다.

## 5. 🔒 호출 상한 — 새로 잡는다

### 앞선 승인 (2026-09-28, 상한 50) — **닫는다**

probe 1 · v3 15 · v4 ≈8~10 · 진단 2 = **≈26~28 / 50.** 남은 여유 ≈22~24.
그 승인은 **v4 계획**에 대한 것이었고 v4 는 중단됐다 — 남은 여유를 v5 로 옮겨 쓰지 않는다.
계획이 바뀌었는데 상한만 이어 쓰면 "무엇에 대한 승인인가"가 흐려진다.

### 새 상한 — 최악의 경우로 센다

judge 1회는 스키마 실패 시 재시도가 붙어 **최대 2건**이다. 중단 조건이 "실패 3건 초과"라
한 팔에서 실패는 **최대 4회**까지 나고 그 4회가 재시도 1건씩을 더한다.

| 단계 | 기본 | 재시도 최악 | 상한 |
|---|---|---|---|
| probe (새 날이라 다시 — `vllm-endpoint.md`) | 1 | +1 | **2** |
| F 소표본 v5 × 3 | 3 | +3 (3건 모두 실패해도 멈추므로 최대 3) | **6** |
| 본 실행 v5 × 30 | 30 | +4 | **34** |
| v3 대조군 × 15 | 15 | +4 | **19** |
| **합계** | | | **61** |

- 상한에 닿으면 거기서 멈추고 다시 묻는다.
- **단계 F 와 본 실행은 승인을 나눠 받는다.** 첫 승인은 probe + 대조군 + F (최대 27).

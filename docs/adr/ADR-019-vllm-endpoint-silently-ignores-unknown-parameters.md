# ADR-019: vLLM 엔드포인트는 미지 파라미터를 조용히 무시한다 — structured output 강제를 매번 실증한다

- **Status:** Accepted
- **Date:** 2026-09-18
- **Decision:** KT Cloud AI Nexus vLLM 엔드포인트가 **모르는 요청 파라미터를 400 으로 거절하지 않고 조용히 무시한다**는 것을 실측으로 확정하고, 그 결과 **structured output 강제가 이름 하나로 사라질 수 있다**는 것을 이 레포의 상시 제약으로 못 박는다. 강제 여부는 문서나 파라미터 이름으로 믿지 않고 **"JSON 을 쓰지 마라" 반증 probe** 로 확인한다. 이 레포가 쓰는 강제 파라미터는 `response_format={"type":"json_schema", ...}` 하나로 고정한다.
- **Scope:** ai-news-ontology (`extraction/vllm.py` 및 이 엔드포인트를 쓰는 모든 코드)
- **Decision Source:** Agent (session-03 실측) / 기록 지시는 Human

---

## Context

### Problem

`gemma-4-31B-it` 이전(ADR-018)의 선행 확인으로 **structured output 을 vLLM 에서
같은 강도로 걸 수 있는가**를 재야 했다 (MARA 사전 등록 §2.1-2). 그 확인 중에 이
엔드포인트의 성질 하나가 드러났다.

> **모르는 파라미터를 보내도 HTTP 200 이 온다.** 400 도, 경고도, 응답 어디에도
> 표시가 없다. 요청은 성공하고, **그 파라미터가 하려던 일만 일어나지 않는다.**

structured output 은 요청 파라미터로 켜는 기능이다. 그래서 이 성질은
**"강제가 꺼져 있는데 성공한 것처럼 보이는 상태"** 를 만든다.

### 왜 이것이 이 레포에서 특히 위험한가

- **실패 신호가 하나도 나지 않는다.** 잘못 부른 호출은 예외를 올리지 않고, 로그에
  남지 않고, 응답 스키마도 정상이다. 모델이 대체로 JSON 을 잘 내기 때문에 **출력만
  보면 강제가 걸린 것과 구분되지 않는다.**
- **틀려도 대부분의 건은 통과한다.** 그래서 소표본에서 안 걸리고, 실패율이 조금
  높게 나올 뿐이다. **그 수치를 "gemma 의 능력"으로 읽게 된다.**
- 이것은 이 레포가 방금 겪은 실패와 **같은 모양**이다. ADR-017 의 승인 게이트는
  있었고 통과했는데, 게이트가 확인해야 할 것을 확인하지 않았다. 여기서도 파라미터는
  보냈고 200 이 왔는데, 그 파라미터가 확인해야 할 것을 확인하지 않는다.

### Constraints

- 엔드포인트는 **관리형**이다(MARA ADR-003). vLLM 버전·빌드 옵션·guided decoding
  백엔드를 우리가 고르지 못하고, 바뀌어도 통보받지 못한다.
- 따라서 **한 번 확인한 사실이 계속 참이라고 가정할 수 없다.** 오늘 `response_format`
  이 강제되더라도 내일 서버가 갱신되면 조용히 무시 대상이 될 수 있고, 그때도
  HTTP 200 이 온다.

---

## Decision

### Selected

- **강제 파라미터는 `response_format={"type":"json_schema", "json_schema":{...}}` 하나로
  고정한다.** 실측에서 강제됨이 확인된 이름이다.
- **`guided_json` 을 쓰지 않는다.** 이 엔드포인트에서 **무시된다** (실측). vLLM 문서
  다수가 아직 이 이름을 쓰기 때문에 검색으로 흘러 들어오기 쉽다.
- **강제 여부는 "반증 probe" 로 확인한다.** 아래 Rationale 참고. 이 판별을
  `tests/test_vllm_client.py` 에 **문서화된 절차**로 두고, 엔드포인트가 필요한
  검사는 기본적으로 돌지 않게 한다(네트워크 의존 테스트를 CI 계약에 넣지 않는다).
- **엔드포인트를 실제로 쓰는 측정 실행은 강제 확인을 선행 조건으로 한다.**
  `.claude/rules/vllm-endpoint.md` 에 절차로 남긴다.

### Rejected — "파라미터를 여러 개 같이 보낸다"

`response_format` 과 `guided_json` 을 함께 보내면 어느 쪽이든 걸릴 것 같지만
**기각한다.** 둘 중 무엇이 실제로 동작했는지 알 수 없게 되고, 그 상태에서 서버가
바뀌면 **언제 강제가 사라졌는지도 알 수 없다.** 무시되는 파라미터를 보내는 것은
보험이 아니라 **관측을 흐리는 행위**다.

---

## Rationale

### 판별을 "스키마를 어겨 보라"로 하면 안 된다

첫 probe 를 그렇게 짰다가 **정반대 결론이 나올 뻔했다.**

스키마(`색` enum, `설명` `minLength:200`)를 주고 "색=초록, 설명=짧게"를 시켰더니
JSON 문법이 깨진 출력이 나왔다 — 문자열이 닫히지 않았고 뒤에 이모지가 붙어 있었다.
**"문법 강제가 없다"로 읽힌다.** 실제로는 반대였다.

> `minLength:200` 이 **문자열을 못 닫게 강제**했고, 모델이 채울 말이 없어 패딩을
> 반복하다 `max_tokens` 에서 잘린 것이다. `finish_reason: "length"`, 2000 토큰 전부
> 패딩. **강제가 너무 잘 걸려서 깨진 출력이 나왔다.**

교훈은 방법론이다. **모델이 지시를 안 따른 것과 디코더가 막은 것은 출력만 보고
구분되지 않는다.** 스키마를 어기라고 시키면 모델의 순종도와 디코더의 강제가 섞인다.

### 그래서 "JSON 을 쓰지 마라"로 판별한다

    프롬프트: "JSON 을 쓰지 마라. 중괄호도 쓰지 마라. 한국어 산문 두 문장으로 답하라."
    스키마  : {"답": {"enum": ["예","아니오"]}}  (required)

- **산문이 나오면 강제가 아니다.** 모델이 지시를 따른 것뿐이다.
- **스키마에 맞는 JSON 이 나오면 강제다.** 모델은 지시를 따르려 했는데 **나갈 수
  없었다**는 뜻이고, 다른 해석이 없다.

이 설계의 값은 **강제와 순종이 서로 반대 방향을 가리키게 만든 것**이다. 결과가
어느 쪽이든 원인이 하나로 특정된다.

### `~/v1/models` 로는 알 수 없다

모델 목록은 `max_model_len` 같은 서빙 파라미터만 준다. guided decoding 백엔드가
켜져 있는지, 어떤 `response_format` 이름을 받는지는 **거기에 없다.** 능력은 선언이
아니라 호출로만 확인된다.

## Evidence

- **Experiment (2026-09-18):** 같은 프롬프트("JSON 쓰지 마라")에 파라미터만 바꿔 4회.

  | 요청 파라미터 | 응답 | 판정 |
  |---|---|---|
  | `response_format={"type":"json_schema", strict:true}` | `{ "답": "아니오" }` | **강제됨** |
  | `structured_outputs={"json": …}` | `{ "답": "아니오" }` | **강제됨** |
  | `guided_json={…}` | `오늘은 하늘이 맑고 햇살이…` (산문) | **무시됨** |
  | `__definitely_not_a_real_param__=12345` | `오늘은 하늘이 맑고 햇살이…` (산문) | **무시됨** |

  마지막 두 줄이 이 ADR 의 근거다. **존재하지 않는 파라미터와 `guided_json` 이
  같은 결과를 냈다** — 서버가 둘을 구분하지 않는다는 뜻이고, 둘 다 HTTP 200 이다.

- **Experiment:** enum 강제 확인. 스키마 `enum: ["빨강","파랑"]` 에 `색=초록` 을
  지시 → `"빨강"` 이 나왔다. 목록 밖 값이 생성되지 않는다.

- **Experiment:** `minLength` 강제 확인. `minLength:200` + `max_tokens:2000` →
  `finish_reason: "length"`, 완성 토큰 2000 전부 소모, 문자열 미종료.
  **수량 제약도 디코딩에서 강제된다.**

- **Experiment:** 실제 스키마(`NewsOntology`, `$defs`/`$ref`/enum/중첩 객체 포함)
  수락 및 pydantic 검증 통과 확인.

- **Production Data:** 30건 재추출 실행(ADR-018)에서 `response_format` 으로만 호출.

## Alternatives

### (가) vLLM 문서를 믿고 파라미터 이름을 고른다

- **Pros:** probe 비용 0.
- **Cons:** 관리형 엔드포인트라 **서버 버전을 우리가 모른다.** `guided_json` 이
  문서에 있고 실제로는 무시된다는 것이 정확히 이 경우다.
- **Rejected because:** 문서가 맞아도 **이 배포에서 맞는지**는 별개다.

### (나) 출력이 JSON 인지로 강제 여부를 판단한다

- **Pros:** 별도 probe 가 필요 없다. 실행 결과로 바로 안다.
- **Cons:** 모델이 대체로 JSON 을 잘 낸다. **강제가 꺼져 있어도 대부분 통과한다.**
- **Rejected because:** 이 판정이 틀리는 방향이 하필 **"괜찮아 보인다"** 쪽이다.

### (다) 서버에 파라미터 검증(strict) 을 켜 달라고 요청한다

- **Pros:** 근본 해결이다. 오타가 400 이 된다.
- **Cons:** 우리 관리 범위가 아니고, 할당이 정부지원 무료 자원이라 협상 여지가 작다.
- **Rejected because:** 지금 할 수 없다. **다만 이 항목은 포기가 아니라 보류다** —
  아래 Review Trigger.

## Consequences

### Positive

- **structured output 강제가 측정의 전제로 명시됐다.** ADR-018 의 ①②가 무엇을
  잰 수치인지 말할 수 있게 됐다.
- **판별 방법이 재사용 가능하다.** 엔드포인트·모델·서버 버전이 바뀌어도 같은 probe
  로 같은 질문에 답할 수 있다.

### Negative

- **강제 확인이 측정 전 절차로 추가된다.** 호출 1건이지만 잊으면 의미가 없어서,
  `.claude/rules/vllm-endpoint.md` 에 절차로 남겼다.
- **오타가 여전히 조용히 통과한다.** 이 ADR 은 그것을 없애지 못하고 **알고 쓰게**
  만들 뿐이다. 코드에서 파라미터 이름을 상수로 모아 두는 것이 실질적인 방어다.

### Risks

- 🔴 **서버가 갱신되면 강제가 조용히 사라질 수 있다.** 통보받지 못하고, 실패
  신호도 없다. 이 경우 ②의 수치가 **모델이 나빠진 것처럼** 보인다.
- 🔴 **`minLength` 강제 + 낮은 `max_tokens` 는 절단을 만든다.** 이 레포의 스키마는
  하한이 작아(`요약` 20자, `근거` 15자) 현재는 안전하지만, 스키마에 큰 하한을
  넣으면 **모델 능력과 무관하게 실패율이 오른다.** 스키마 변경 시 같이 본다.

## Review Trigger

- **Recheck if:** 엔드포인트 주소·서버 버전·모델이 바뀌는 경우. **반증 probe 를
  다시 돌린다.** 이전 결과를 이월하지 않는다.
- **Recheck if:** 스키마에 큰 `minLength`/`minItems` 를 추가하는 경우 (절단 위험).
- **Recheck if:** 엔드포인트가 파라미터 검증을 켜는 경우 — (다)가 되살아난다.
- **Expires:** 2026년 말. KT Cloud AI Nexus 할당이 정부지원 GPU 자원이라 그 시점에
  엔드포인트가 유지되는지 자체가 미정이다 (MARA ADR-003).

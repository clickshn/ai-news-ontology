# ADR-012: 골든셋은 사람이 확정한 항목만 채점하고, 채점 방식을 필드별로 다르게 둔다

- **Status:** Accepted
- **Date:** 2026-08-30
- **Decision:** 골든셋 항목에 `status: draft` / `confirmed` 를 두고 채점기는 기본적으로 `confirmed` 만 읽는다. 채점 방식은 필드마다 다르게 한다 — `기술영역`=Jaccard, `발표유형`=정확 일치, `영향도`=정확 1.0/±1 0.5, `관련기업`·`관련기존기술`=기록만.
- **Scope:** ai-news-ontology (eval)
- **Decision Source:** Human

> 이관: README 결정 로그 **D-039**, **D-040**. 둘 다 "점수가 무엇을 뜻하는가"를 정하는
> 결정이라 하나로 묶었다. 원본 날짜와 근거는 그대로다.

---

## Context

### Problem

"모델 출력은 정답이 아니다"는 원칙이 지금까지 **문서에만** 있었다. 초안이 실수로
채점에 섞이면 eval 이 모델의 자기 채점이 되는데, 그때 **점수는 높게 나오고 그 사실이
결과 어디에도 드러나지 않는다.** 동시에 필드마다 성질이 달라 한 가지 채점 방식으로는
정보가 사라졌다.

### Constraints

- 조용히 틀리는 종류의 실패는 사람의 주의력으로 막을 수 없다.
- `기술영역` 은 다중값이라 완전일치만 보면 2/3 맞춘 것과 0/3 이 같은 점수가 된다.
- `영향도` 는 **순서형**이라 2 vs 3 과 2 vs 5 를 같은 오답으로 치면 정보가 사라진다 —
  1칸 차이는 사람끼리도 갈린다.
- 자유 태그(`관련기존기술`)는 정답 집합이 닫히지 않아 모델이 더 뽑았다고 틀린 게 아니다.
- `관련기업` 은 엔티티 경계가 아직 관찰 중이다(오픈소스 프로젝트 포함 여부).

## Decision

### Selected

- **Technology:** pydantic 스키마 검증 + 순수 함수 채점기
- **Architecture:** 확정 게이트와 채점 방식을 **코드로** 강제한다. `confirmed` 승격 시
  빈칸·`<<채워주세요>>` 잔여를 스키마가 거부한다.
- **Implementation:** `eval/schema.py`, `eval/runner.py: compare_ontology()`.
  비교 전 `normalization_key` 로 표기 노이즈를 흡수한다 (ADR-009 와 같은 키).
  채점에서 뺀 두 필드는 `graded=false` 로 **기록은 남긴다.**

## Rationale

1. 초안이 채점에 섞이면 eval 이 모델의 자기 채점이 된다 — 조용히 틀리는 종류라
   코드로 막아야 한다. 채점기가 "정답이 없음"과 "정답이 X"를 구분하지 못하면
   accuracy 가 의미를 잃는다.
2. 필드의 성질이 다르면 채점 방식도 달라야 한다. 다중값을 완전일치로 보면 추이가
   안 보이고, 순서형을 이분법으로 보면 거리 정보가 사라진다.
3. 정답 집합이 닫히지 않은 필드는 임계값에서 뺀다 — 닫히지 않은 집합에 정확도를
   매기면 숫자가 무엇을 뜻하는지 알 수 없다.

## Alternatives

### 파일명 규칙(`.draft.json`)으로 구분

- **Pros:** 스키마를 안 건드린다.
- **Cons:** 규칙을 지키는지는 사람이 본다.
- **Rejected because:** 조용히 틀리는 실패를 사람의 주의력에 맡기게 된다.

### 전부 judge 로 채점

- **Pros:** 채점 로직이 하나다.
- **Cons:** 통제어휘 필드는 judge 를 쓸 이유가 없고 비용만 든다.
- **Rejected because:** 결정적으로 비교 가능한 것에 확률적 채점을 쓰는 낭비다
  (README D-006).

## Consequences

### Positive

- `field_accuracy` 가 "무엇을 어떻게 세었는지" 설명 가능한 지표가 됐다.

### Negative

- 채점 대상 필드가 3개로 줄어 골든셋 1건이 주는 정보가 작아졌다.
- **채점 방식을 바꾸면 과거 점수와 비교할 수 없다.** 지표 정의 변경은 추이의 단절이다.

## Reversibility

- **Reversible:** Partial
- **Rollback:** 채점 방식을 되돌리면 과거 실행의 점수와 새 점수를 같은 축에서 읽을 수
  없다. 골든셋 라벨 자체는 남는다.
- **Migration Cost:** Medium

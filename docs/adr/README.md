# ADR (Architecture Decision Record)

되돌리기 비용이 있는 결정을 기록한다. 형식은 `adr-recorder` 스킬의 템플릿을 따르고
파일명은 `ADR-NNN-slug.md` 다.

## README 결정 로그와의 관계

**둘은 대체 관계가 아니다.** 경계는 `docs/governance.md` 가 정한 대로 **되돌리기
비용**이다.

| | 무엇이 들어가나 |
|---|---|
| `README.md` 결정 로그 (`D-XXX`) | 일상적인 설계 판단 전부. 시간순 서사이며 계속 여기에 쓴다 |
| `docs/adr/` | 그중 **되돌리는 데 재작업이 드는 것** — 재라벨링·재추출·재인덱싱·과거 측정값 무효화가 따라오는 결정 |

번복은 양쪽 모두 **기존 기록을 지우지 않는다.** 상태를 바꾸고 사유를 남긴다
(ADR-011 이 D-003 의 부분 번복을 그대로 안고 간 것이 그 예다).

## 이관 (2026-09-17)

README 결정 로그 **D-001 ~ D-060(60건)** 을 위 기준으로 걸러 **16건의 ADR** 로 옮겼다.
이관은 새 분석이 아니라 **기록의 형식 변환**이므로, 원본에 적힌 날짜와 근거를 그대로
쓰고 원본에 없는 정보를 새로 만들지 않았다. **원본 결정 로그는 그대로 둔다.**

같은 결정이 D 번호 여럿으로 쪼개져 있으면 한 ADR 로 합쳤다.

| ADR | 다루는 결정 | 원본 D |
|---|---|---|

| ADR-007 | `요약` 을 별도 필드로 | D-027 |

MARA 쪽에서 내려졌고 정본이 그쪽에 있다. 이쪽 구현 규칙은 `.claude/rules/export.md`
와 `export/README.md` 에 있다.

## 이관하지 않은 D 번호 — 28건

**임의 누락이 아니라 위 기준을 적용한 결과**임을 보이기 위해 전부 적는다. 이 항목들은
README 결정 로그에 그대로 살아 있다.

| D | 결정 | 왜 기준에 안 걸리나 |
|---|---|---|
| D-005 | 평가 패키지명을 `eval` 로 | 이름 선택. 되돌리면 import 경로만 바뀌고 데이터·라벨은 그대로다 |
| D-006 | 채점을 골든셋 대조와 judge 두 축으로 분리 | ADR-012 의 전제이고 그 Alternatives 에 근거가 그대로 들어가 있다 |
| D-007 | frontmatter `영향도` 를 두 키로 편다 | ADR-011 과 같은 층위의 직렬화 표현이고 되돌리기 비용도 거기에 포함된다 |
| D-008 | observability 선택적 의존성 | 관측 부재가 파이프라인 장애가 되지 않게 하는 방어. 되돌려도 산출물이 틀려지지 않는다 |
| D-011 | `정규명` optional 로 변경 | ADR-009 가 대체한 중간 단계다. 최종 규칙은 ADR-009 에 있다 |
| D-016 | 스킵 항목을 `SkipRecord` 로 | 인터페이스만 둔 관측 준비. ADR-006 Consequences 에 들어 있다 |
| D-019 | `Usage` 에 thinking/latency/캐시 분리 기록 | 관측 항목 추가. 되돌려도 과거 데이터가 틀려지지 않는다 |
| D-020 | `관련기존기술` 영어 표준형 통일 | 사전 없는 자유 필드의 표기 규칙이라 프롬프트 층위 변경이다. ADR-008 정책의 적용 사례 |
| D-024 | v2 프롬프트 실전 검증 완료 | 결정이 아니라 실행 결과 기록 |
| D-030 | `관련기업` 위키링크를 canonical 로 | ADR-009 의 귀결. 링크 대상만 바꾸면 되돌아간다 |
| D-031 | 파일명 슬러그에서 한글을 로마자화하지 않음 | 표기 선택. 동일성 판정은 `source_url` 이라(ADR-010) 되돌려도 노트가 유실되지 않는다 |
| D-034 | README 상태 표기에 버전 번호를 쓰지 않음 | 문서 관례 |
| D-035 | 미등록 기업 기록을 파이프라인 층에 | ADR-009 Architecture 에 한 줄로 흡수했다 |
| D-036 | 두 로그 파일의 쓰기 방식을 다르게 | 로컬 산출물 운영 규칙. `docs/governance.md` 로 갔다 |
| D-037 | 슬러그 길이 24 → 40 | 파라미터 조정 |
| D-038 | 관측 이전 미등록 3건을 소급 기록하지 않음 | 일회성 판단 |
| D-042 | judge 비결정성을 기록만 함 | ADR-014 Alternatives 에 포함됐다 |
| D-043 | 1건으로 자기 편향을 판단하지 않음 | ADR-014 Rationale 에 포함됐다 |
| D-044 | `JudgeUsage` 를 채점 결과에 저장 | 관측 항목 추가 |
| D-046 | `영향도` 라벨에 루브릭 밖 기준을 섞지 않음 | 라벨링 가이드라인. 과거 라벨을 고치지 않기로 해 소급 비용이 없다 |
| D-047 | 골든셋에 `labeling_guideline` 필드 | D-046 의 구현 수단 |
| D-049 | D-042 를 부분 해결로 내림 | 상태 갱신. 실측은 ADR-014 Evidence 에 들어 있다 |
| D-050 | 반복 채점을 표본 증가로 세지 않음 | 집계 규칙. ADR-012 References 에 포함 |
| D-051 | 슬롯 집계기를 순수 함수로 분리 | 구현 구조. ADR-014 Consequences 에 한 줄 |
| D-053 | 골든셋 2번째 항목 확정 | 데이터 작업 기록 |
| D-054 | 축별 gap 을 함께 본다 | 지표 해석 규칙. 새 지표를 만들지 않았다 |
| D-055 | 프롬프트의 "AI 뉴스" 문구를 지금 고치지 않음 | 미결 항목. ADR-004 Negative 에 사례로 인용했다 |
| D-060 | 완결성 루브릭에 "부분 충족" 칸이 없음 | 미해결 결함 기록. ADR-014 Negative 에 인용했다 |

경계에 가까운 것은 **D-020**(자유 필드 표기 규칙)과 **D-046**(라벨링 가이드라인)이다.
둘 다 과거 산출물을 소급해서 틀리게 만들지 않는다는 점에서 기준 밖으로 뒀다.

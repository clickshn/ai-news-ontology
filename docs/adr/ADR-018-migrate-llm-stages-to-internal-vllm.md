# ADR-018: 세 LLM 단계를 전부 내부 vLLM 으로 이전한다 — 벤더 호출 지점 5개를 0개로

- **Status:** Accepted
- **Date:** 2026-09-18
- **Decision:** 관련성 게이트 / 추출 / eval judge 세 단계를 외부 벤더(Anthropic)에서 **내부 vLLM(`gemma-4-31B-it`, KT Cloud AI Nexus)** 으로 이전한다. 클라이언트 생성을 `extraction/llm.py: client_from_config` 한 곳으로 모으고, OpenAI 호환 구현체(`extraction/vllm.py`)를 **새 의존성 없이** stdlib 위에 얹는다. 품질은 MARA 사전 등록의 기준으로 판정했고 **합격**이다.
- **Scope:** ai-news-ontology (`extraction/`, `export/`, `eval/`, `config.yaml`, `.env`)
- **Decision Source:** Human (session-03 작업 지시) / 판정 기준은 MARA 사전 등록

> **목적은 비용 절감이 아니라 전제 위반 해소다.** 비용을 이유로 적으면 판정 기준이
> 흔들린다 — "품질이 좀 떨어져도 싸니까"가 들어올 자리가 생긴다 (사전 등록 §1).

---

## Context

### Problem

이 레포는 `multiagent-research-lab`(MARA)의 코퍼스를 만드는 **생산자**다. MARA 의
전제는 **외부 LLM 벤더 비의존**(MARA ADR-002/ADR-021)인데, **그 코퍼스를 만드는 단계
전부가 벤더를 가리키고 있었다.** MARA Session 0.5a 의 위반이 정확히 그 지점에서 났고,
**실행 코드가 이 레포였다.**

ADR-017 이 게이트를 세웠지만 **게이트는 해결이 아니라 유예다.** 그 ADR 스스로
적었듯이 `anthropic` SDK 가 설치돼 있고 키가 `.env` 에 있는 한 **스크립트 파일 하나로
두 계층 밖에서 진짜 호출이 나간다.** 경로 자체를 없애는 것은 이전뿐이다.

### 범위는 추정이 아니라 실측 목록이다

ADR-017 의 "차단 상태 1회 실행"이 남긴 표(session-02 §3.1)를 그대로 썼다.

| 단계 | 클라이언트 **생성** | **호출** |
|---|---|---|
| `relevance_gate` | `extraction/extractor.py:318`, `export/runner.py:195` | `extractor.py:214` |
| `extraction` | `extraction/extractor.py:333`, `export/runner.py:196` | `extractor.py:145` |
| `eval_judge` | `eval/runner.py:316` | `eval/runner.py:258` |

> 🚩 **"단계 3개"로 세면 `export/runner.py` 의 두 줄이 조용히 빠진다.**
> 생성 지점은 셋이 아니라 **다섯**이다. `export/` 경로가 게이트와 추출 클라이언트를
> **별도 줄에서 다시 만들기** 때문이고, 이것이 이 ADR 이 팩토리를 도입한 직접적인
> 이유다 — 생성이 호출부마다 흩어져 있으면 프로바이더를 바꿀 때 한 줄이 남는다.

### Constraints

- **프롬프트를 고칠 수 없다.** 고치면 대조의 변수가 둘이 된다 (사전 등록 §2.1-1).
  실행에 쓰인 프롬프트 버전은 수정하지 않는다는 규칙(D-010/D-023)과도 맞물린다.
- **재추출 입력을 새로 만들지 않는다.** 보존소에 원문이 있다 (ADR-015).
- **`openai` SDK 를 설치하면 안 된다** — 근거는 아래 Rationale.
- 엔드포인트는 관리형이고 **모르는 파라미터를 조용히 무시한다** (ADR-019).

## Decision

### Selected

- **Technology:** OpenAI 호환 `/v1/chat/completions` 를 `urllib.request` 로 직접 호출.
  **새 의존성 0개.** `extraction/vllm.py: VLLMClient` 가 기존 `LLMClient` Protocol
  (ADR-003)을 만족하므로 **호출부는 한 줄도 바뀌지 않는다.**
- **Architecture:** 클라이언트 생성을 **`client_from_config(config, stage=...)` 한 곳**으로
  모았다. `llm.provider` 가 `"vllm"` | `"anthropic"` 를 고른다. 생성 지점 5개가
  전부 이 함수를 지난다.
- **Implementation:**
  - `extraction/vllm.py` — 구조화 출력은 `response_format={"type":"json_schema"}`,
    스키마는 `model_json_schema(by_alias=True)`(한국어 alias 가 계약의 표면, D-003).
    검증은 우리 쪽 pydantic 이 한다.
  - 재시도를 **벤더 쪽과 같게** 맞췄다 — 오류 되먹여 1회 → `SchemaMismatchError(attempts=2)`.
    되먹이는 메시지 문구까지 같다 (사전 등록 §2.1-3).
  - `config.yaml`: `llm.provider: vllm`, 세 단계 모델 `gemma-4-31B-it`,
    `eval.judge_model` 도 함께 교체.
  - `VLLM_BASE` / `VLLM_MODEL` 은 `.env` 로만 주입한다. **URL 자체가 자격증명**이라
    (MARA ADR-010) `config.yaml`·코드·`.env.example` 에 두지 않는다.
  - `export/replay.py` — 보존소 입력을 다른 프로바이더로 재추출하는 대조 실행기.
    응답 원본을 변환 전에 디스크로 내린다 (D-052).

### Rejected — `openai` SDK 를 쓴다

OpenAI 호환 엔드포인트를 부르는 가장 흔한 방법이지만 기각한다.

1. **그 SDK 의 기본 `base_url` 이 벤더다.** 설치하는 순간 "설정 한 줄로 벤더에 닿는
   문"이 하나 더 생긴다. **이 레포가 방금 `anthropic` 으로 겪은 문제를 한 번 더
   만드는 것**이고, 벤더 경로를 없애려는 작업이 새 벤더 경로를 여는 셈이 된다.
2. **게이트가 그 SDK 를 구분하지 못한다.** `.claude/hooks/check-external-llm.sh` 가
   `import openai` 와 `OpenAI(` 를 차단 대상으로 들고 있다. 정상 사용과 위반이 같은
   문자열이 되면 D-061 에서 `anthropic` 으로 겪은 정탐·오탐 충돌이 재발하고, 그때는
   **훅에서 패턴을 빼는 수밖에 없어진다.**
3. 필요한 것은 `POST /chat/completions` 하나다. 표준 라이브러리로 충분하다.

## Rationale

### 왜 팩토리 한 곳인가 — 실측 목록이 가르쳐 준 것

이전 범위가 "단계 3개"가 아니라 **"생성 지점 5개"** 였다는 사실 자체가 설계 결함의
증거다. 같은 단계의 클라이언트를 두 파일이 각자 만들고 있었고, **그 사실은 코드를
읽어서가 아니라 게이트를 걸고 실제로 돌려서** 드러났다 (ADR-017 Evidence).

팩토리는 "깔끔해서"가 아니라 **다음 교체 때 같은 일이 반복되지 않게** 두는 것이다.
프로바이더가 또 바뀔 때(할당 종료·모델 변경) 고칠 곳이 한 곳이어야 한다.

### 왜 judge 도 같이 옮기나

`eval.judge_model` 이 벤더를 가리키는 한 **판정하는 행위 자체가 같은 위반**이다.
"이전이 잘 됐는지 재는" 실행이 이전이 없애려는 위반을 저지르는 구조가 된다.

⚠️ **judge 와 후보가 같은 모델이 되어 자기 선호 편향이 생긴다.** 사전 등록 §3.3 이
미리 적어 둔 대로 judge 점수는 참고값이고, 합격은 ①②가 가른다. 이번 실행에서는
**③을 아예 측정하지 않았다** — 근거는 `docs/eval/run-log-session-03.md` §4.

### 왜 `temperature=0` 인가

Opus 5 는 이 파라미터를 거부했고(400, D-033) gemma 는 받는다. 게이트에 0 을 쓴 것과
같은 이유다 — **같은 입력이 실행마다 다르게 판정되면 안 된다** (D-032).

**다만 이것은 "모델만 바꿨다"가 아니게 만드는 차이다.** `effort`/`thinking` 도 대응
개념이 없어 사라졌다. 모델을 바꾸면 받는 파라미터가 달라져 **변수가 반드시 둘 이상이
된다** — 사전 등록의 "한 번에 하나만 바꾼다"가 모델 교체에서는 문자 그대로 성립하지
않는다. 감추지 않고 결과에 적었다 (run-log §5).

## Evidence

- **Experiment (2026-09-18):** 보존된 30건과 **동일 입력**으로 vLLM 재추출.
  `prompt_sha256 = 9ff5a9d3…1c5976` — 보존된 30건 전부와 일치(프롬프트 무변경 확인).

  | 지표 | 합격선 | 결과 |
  |---|---|---|
  | ① 통제어휘 이탈률 | ≤ 5% | **0.00%** (값 86개 중 0개) |
  | ② structured output 실패율 | ≤ 10% | **0.00%** (30건 중 0건, 재시도 0, 절단 0) |
  | ③ judge 점수 차이 | ≤ 0.5 (참고값) | **미측정** — Opus 측 골든셋 예측이 없어 "차이"를 계산할 수 없다 |

  → **① 그리고 ② → 합격** (사전 등록 §3.1).

- **Experiment:** ①은 사전 등록 §3① 이 지정한 판정기로 쟀다 — MARA
  `src/tools/contract_import.py: validate_record` **위반 0건**. 생산자 쪽
  `export/conformance.py: check_10_vocab` 도 PASS. **새 판정기를 만들지 않았다.**
  MARA 레포는 읽기만 했다.

- 🚩 **①의 판별력이 없다는 것이 이 실행의 실질적 발견이다.** enum 이 디코딩에서
  강제되므로 목록 밖 값은 **생성 자체가 불가능**하고, Opus 쪽도 같은 상태였다.
  0%는 gemma 의 어휘 준수가 아니라 **디코더가 어기게 놔두지 않았다는 사실**을 잰
  값이다. 사전 등록 §2.1-2 가 걱정한 것이 실제로 일어난 사례로 기록한다.

- ⚠️ **②의 Opus 기준선은 실측이 아니라 가정이다.** 사전 등록 §3② 이 *"기록이 없다와
  0이었다는 다르다"* 고 경고하며 양쪽 모두 카운터를 남기라고 했는데, **한쪽만
  남겼다.** Opus 실행은 지나갔고 다시 돌리는 것은 벤더 호출이라 할 수 없다.
  이 비대칭은 **해소 불가**다.

- **Production Data (합격선 밖, 판정에 넣지 않는다):** 발표유형 일치 26/30(87%),
  기술영역 집합 완전일치 10/30(33%, 다만 30/30 이 1개 이상 겹침), 영향도 동일
  21/30(70%, MAE 0.30), 요약 길이 중앙 186자→129자, `관련기존기술` 개수 1.9→0.9개.
  요약 문체 규칙 위반 0건.

- **Cost:** **$0.** 엔드포인트가 정부지원 GPU 자원 할당으로 무료다 (MARA ADR-003).
  지연은 중앙값 17.0초 → **3.4초**.

- **Production Data:** `pytest tests/ -q` — 이전 전 442 passed. 이전으로 **19건이
  깨졌고 전부 계약이 뒤집힌 것**이라 되돌리지 않고 갱신했다. 그중 6건이
  `test_blocked_state_run.py` 이고, **그 파일이 깨졌다는 사실이 곧 벤더 호출 지점이
  0이 됐다는 증거**다 (아래 Consequences).

## Alternatives

### (가) 게이트만 유지하고 벤더를 계속 쓴다

- **Pros:** 품질이 검증된 상태를 유지한다. 작업량 0.
- **Cons:** ADR-017 이 스스로 적은 대로 **게이트는 유예다.** 스크립트 파일 하나면
  두 계층 밖에서 호출이 나간다. MARA 의 전제는 계속 깨진 상태로 남는다.
- **Rejected because:** 재발 가능성을 낮출 뿐 **원인을 없애지 못한다.**

### (나) 추출만 옮기고 게이트·judge 는 벤더에 둔다

- **Pros:** 비용이 큰 단계만 옮겨 효과가 대부분이다. 판정기(judge)의 품질을 지킨다.
- **Cons:** `eval.judge_model` 이 벤더를 가리키는 한 **판정하는 행위가 같은 위반**이다.
  게이트도 마찬가지다. "전제 위반 해소"가 목적인데 위반이 남는다.
- **Rejected because:** 목적이 비용이면 맞는 답이지만, 목적은 비용이 아니다.

### (다) `openai` SDK 를 쓴다

- 위 "Rejected" 절 참고. **새 벤더 경로를 여는 것**이 기각 사유다.

### (라) LiteLLM 을 쓴다 (MARA 와 같은 방식)

- **Pros:** 두 레포의 프로바이더 계층이 같아진다.
- **Cons:** 무거운 새 의존성이고, **두 레포는 코드를 공유하지 않고 파일 형식 하나만
  공유한다**(MARA ADR-018). 구현을 맞추는 것은 그 전제를 흐린다. 필요한 것은
  엔드포인트 하나에 대한 `POST` 하나다.
- **Rejected because:** 얻는 것보다 끌고 오는 것이 크다.

## Consequences

### Positive

- **벤더 호출 지점이 5개에서 0개가 됐다.** `config.yaml` 이 벤더를 가리키지 않고,
  `anthropic` SDK 는 롤백 경로로만 남는다.
- **MARA 의 전제 위반이 해소됐다.** 코퍼스 생성이 소비자와 같은 원칙 위에 선다.
- **2단계 220건의 약 $16 승인 자체가 없어졌다** (사전 등록 §5 합격 경로). 다만 MARA
  session-10 §8.3 의 **측정 설계상 연기**는 별개 사유로 유효하고, 둘 다 풀려야 한다.
- **비용 $0, 지연 1/5.** 부수 효과이고 판정 근거가 아니다.
- **프로바이더 교체 지점이 한 곳이 됐다.** 다음 교체(할당 종료 등)의 범위가 줄었다.

### Negative

- **`test_blocked_state_run.py` 의 계약이 뒤집혔다.** "진입점이 벤더 호출 전에
  멈춘다"가 더 이상 참이 아니다 — 멈출 벤더 호출이 없다. 이 파일을 **"진입점이
  내부 엔드포인트 클라이언트를 만들고, 벤더 클라이언트를 만들지 않는다"** 로 다시
  썼다. 되돌린 것이 아니라 **새 계약으로 갱신**한 것이다.
- **judge 와 후보가 같은 모델이 됐다.** 자기 선호 편향이 구조적으로 존재한다.
  D-049 의 judge 비결정성 실측은 **벤더 judge 기준**이라 모델이 바뀐 지금 다시 재야
  한다. 이번에는 재지 않았다.
- **`관련기존기술` 표기 품질이 떨어진다** — 개수 1.9→0.9, `LVLM` 같은 약어.
  D-020 의 "영어 표준형 통일"이 gemma 에서 약하게 지켜진다. **자유 필드라 ①②에
  잡히지 않는다.**
- **품질 지표가 강제가 닿는 층에서만 검증됐다.** ①②는 둘 다 디코더가 보장하는
  영역이고, 라벨 정확도는 골든셋 3건으로는 판정할 수 없다.

### Risks

- 🔴 **되돌리기가 너무 쉽다.** `llm.provider` 한 줄이다. **설정 변경이 아니라 전제
  변경**이라는 것을 `config.yaml` 주석·governance·`.claude/rules/` 세 곳에 적었지만,
  적는 것으로 막히지 않는다. `extraction/egress.py` 의 기본 차단이 실제 방어선이다.
  > ⚠️ **부분 정정 (2026-09-21, 아래 Amendment 1).** 이 서술은 작성 시점에 **사실이
  > 아니었다** — 한 줄로 되돌리면 세 단계 전부 벤더가 거부하는 요청을 만들었다.
  > 마찰이 있어서가 아니라 **경로가 깨져 있어서** 어려웠던 것이고, 그것은 안전장치가
  > 아니다. ADR-020 이 경로를 복구했고, 이제 이 서술이 참이다.
- 🔴 **엔드포인트가 모르는 파라미터를 조용히 무시한다** (ADR-019). 파라미터 이름
  하나만 틀려도 강제가 사라지는데 HTTP 200 이 온다.
- 🔴 **`VLLM_BASE` 가 두 레포의 `.env` 에 중복 존재한다.** 둘 다 `.gitignore` 대상이라
  동기화 장치가 없다. 한쪽이 바뀌면 다른 쪽은 조용히 옛 값을 쓴다.
- 🔴 **2026년 말 할당 종료.** 엔드포인트가 정부지원 GPU 자원이라 그 시점에 유지되는지
  자체가 미정이다 (MARA ADR-003). 그때 두 레포가 **따로** 끊긴다.
- **골든셋 3건으로는 라벨 정확도를 판정할 수 없다.** 발표유형 불일치 4건 중 어느
  쪽이 맞는지 지금 알 수 없다.

## Amendment 1 — 롤백 경로가 런타임에 깨져 있었다 (2026-09-21)

**무엇이 틀렸나.** Positive 의 "`anthropic` SDK 는 롤백 경로로만 남는다"와 Risks 의
"`llm.provider` 한 줄이다"는 **검증되지 않은 서술**이었다. 실제로 그 한 줄을 바꾸면
세 단계가 전부 벤더가 거부할 요청을 만들었다.

| 단계 | 롤백 시 나가던 요청 | 결과 |
|---|---|---|
| `relevance_gate` | `model: gemma-4-31B-it` + `temperature: 0` | 벤더에 없는 모델 |
| `extraction` | `model: gemma-4-31B-it` + `temperature: 0` | 벤더에 없는 모델 |
| `eval_judge` | `model: claude-opus-5` + `temperature: 0` | 400 (D-033) |

원인은 이 ADR 의 Implementation 두 줄이다.

- `config.yaml` 에 `temperature: 0` 을 넣었다 — vLLM 은 받고 Opus 5 는 거부한다.
  모델별 지원 범위를 **호출부가 알고 맞춰 넘기는** 구조였으므로, 설정이 vLLM 기준으로
  채워지는 순간 그 지식이 어디에도 남지 않았다.
- **세 단계의 `model` 을 제자리에 덮어썼다.** 벤더 모델명은 `# 이전: claude-opus-5`
  라는 **주석으로만** 남았고, 주석은 롤백 시 아무 일도 하지 않는다.

**왜 안 걸렸나.** 롤백 경로에 테스트가 **0건**이었다. 이전 자체는 대조 실행까지
측정했지만(Evidence), **되돌아가는 쪽은 한 번도 실행되지 않았다.** ADR-017 의 교훈과
같은 모양이다 — 장치가 있었고 적혀 있었는데, 그것이 동작하는지 확인하는 주체가 없었다.

**무엇이 바뀌었나.** ADR-020 이 판정 기준을 프로바이더에서 **모델 능력**으로 옮기고,
벤더 모델명을 주석이 아니라 `vendor_model` 키로 복원했다. 롤백 경로 테스트 12건이
`tests/test_rollback_path.py` 에 생겼다.

**이 ADR 의 결정 자체는 유효하다.** 이전(vLLM 으로의 이동)은 번복되지 않았고 기본
경로의 요청도 바뀌지 않았다. 정정 대상은 **롤백 경로에 대한 서술**뿐이다.

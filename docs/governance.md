# 거버넌스 규칙 — ai-news-ontology

이 문서는 **에이전트와 사람이 함께 따르는 작업 규칙**이다. `CLAUDE.md` 의
`@docs/governance.md` import 로 매 세션 자동 로드되며, `CLAUDE.md` 와 달리
**버전 관리 대상**이다 — 규칙 변경이 커밋 이력에 남고 레포를 보는 사람에게도
그대로 전달된다.

규칙을 바꿀 때는 이 파일을 고친다. `CLAUDE.md` 에는 개인 메모만 둔다.

> 이 분리는 `multiagent-research-lab`(MARA)에서 가져왔다. 그쪽에서 두 세션에 걸쳐
> 제기됐던 문제가 "규칙이 `.gitignore` 된 파일에만 있어서 버전 관리가 안 된다"였고,
> 같은 문제가 이 레포에도 그대로 있었다.

## 승인 게이트 — API 호출

실제 LLM API 를 호출하는 작업(LLM 추출, relevance gate, eval judge 실행,
프롬프트 테스트용 실호출 등)을 하기 전에는 반드시 먼저 아래 **6항목 전부**를
알려주고 확인을 받는다.

확인 없이 API 를 호출하지 않는다. 코드 작성, 파일 읽기/쓰기, mock 기반 테스트
실행은 확인 없이 진행해도 된다 — **실제 API 호출만 예외**다.

### 게이트 양식 — 필수 항목 (순서를 지킨다)

> **1번을 건너뛰지 않는다.** MARA Session 0.5a 에서 2~6번은 전부 정확히 답변됐고
> 승인도 받았지만, 1번이 양식에 없어서 규칙 위반이 게이트를 통과했다. **게이트가
> 있었고 통과했는데, 게이트가 확인해야 할 것을 확인하지 않았다.** 그 위반이 난
> 코드가 이 레포다 (ADR-017, MARA ADR-021).

| # | 항목 | 답이 이러면 |
|---|---|---|
| **1** | **대상 엔드포인트가 내부 vLLM(`VLLM_BASE`)인가?** | **아니오 = 승인 대상이 아니라 규칙 위반이다.** 여기서 멈추고 사용자에게 전제 자체를 묻는다 |
| 2 | 나가는 데이터의 범위 (공개 / 합성 / 사내 / 고객) | 공개 RSS·Atom 피드 자료 외가 하나라도 있으면 중단 ("로컬 산출물 취급" 참고) |
| 3 | 목적 (무엇을 위한 호출인지) | |
| 4 | 모델명 (예: `claude-haiku-4-5-20251001`) | |
| 5 | 호출 건수 | **탐색적 호출이면 정확한 수가 아니라 상한을 승인받는다** (아래) |
| 6 | 예상 비용 (토큰 추정치 기반) | |

> **탐색적 호출은 상한으로 받는다 (5번).** 무엇을 확인해야 하는지가 호출 결과에
> 달려 있는 경우 — 엔드포인트 능력 확인, 형식 판별 probe 같은 것 — 건수를 미리 알 수
> 없다. **모르는 것을 정확한 수로 적으면 그 수가 지켜지지 않고 사후 보고가 된다.**
> session-03 에서 probe 4건을 승인받고 9건을 썼다: 1차 probe 의 결과가 **정반대
> 결론**으로 읽힐 상태여서 확정하는 데 5건이 더 들었다. 이럴 때는 "최대 N건"으로
> 받고, 상한을 넘게 되면 거기서 멈추고 다시 묻는다.

**모델명(4번)으로 1번을 대신하지 않는다.** 같은 모델 이름이 내부 엔드포인트에도
벤더 엔드포인트에도 있을 수 있다. **판정 기준은 이름이 아니라 목적지다.**

> ✅ **2026-09-18 이후 1번의 답은 "예"다.** 세 단계(관련성 게이트 / 추출 / eval judge)가
> 전부 내부 vLLM(`VLLM_BASE`, `gemma-4-31B-it`)을 가리킨다 (ADR-018). 벤더 호출 지점은
> **0개**다.
>
> ⚠️ **그래도 이 양식이 없어지지 않는다.** `anthropic` SDK 는 여전히 설치돼 있고
> `config.yaml` 의 `llm.provider` 한 줄로 되돌아간다. 되돌리면 1번의 답이 다시
> "아니오"가 되고, 그건 설정 변경이 아니라 **전제 변경**이다. `extraction/egress.py`
> 의 기본 차단은 그대로 두고, 이제 무게가 `assert_internal_endpoint`(목적지 검사)
> 쪽으로 옮겨 갔다.

### 기본 차단 — 승인은 파일로 연다

`extraction/egress.py` 가 **벤더 클라이언트 생성 시점에** 막는다. 승인을 받았다면
`.claude/external-llm-approved` 를 만들고 진행하고, **끝나면 지운다**(1회용).
`.claude/hooks/check-external-llm.sh` 가 도구 계층에서 같은 판정을 한다.
막지 못하는 범위까지 포함한 상세는 `.claude/rules/external-llm.md` 에 있다.

판단이 애매하면 기준은 둘이다: **이 동작이 새로운 비용이나 되돌리기 어려운 외부
상태를 만드는가**, 그리고 **데이터가 어느 벤더의 모델로 향하는가.** 하나라도
해당하면 승인을 받는다.

### 새 게이트를 만들 때 — 크기를 재는가, 가부를 가르는가

승인 양식을 새로 설계하거나 항목을 추가할 때는 **각 항목이 둘 중 어느 쪽인지 먼저
가른다.**

- **크기를 재는 항목** (건수·비용·규모) — 규모를 조절한다. **위반을 막지 못한다.**
- **가부를 가르는 항목** (목적지·데이터 범위) — 해도 되는 일인지를 판정한다.

**가부 항목이 없으면 그 게이트는 통과해도 아무것도 보증하지 않는다.** 가부 항목은
**1번 자리**에 둔다. 위 6항목 양식이 이 규칙의 적용 결과다 — MARA Session 0.5a 에서
2~6번(크기)은 전부 정확히 답변되고 승인까지 났지만 1번(가부)이 없어서 규칙 위반이
게이트를 통과했다 (ADR-017).

### 규모가 큰 호출은 단계로 쪼갠다

스키마·형식 결함은 표본 수에 비례해서 드러나지 않는다. 30건에서 안 걸리는 형식
결함은 250건에서도 대체로 안 걸리고, 반대로 250건을 다 쓴 뒤에 결함을 찾으면
**같은 비용을 두 번 낸다.** 그래서 큰 실행은 한 번에 승인받지 않고 나눈다.

- 검증 전용 소표본을 먼저 돌려 형식을 확정하고, 결과를 보여준 뒤
- 본 실행은 **별도 승인**을 받는다.

출력 계약 1단계/2단계 게이트가 이 원칙의 적용 사례다 (MARA ADR-018).

### 모델마다 받는 파라미터가 다르다

`claude-opus-5` 는 `temperature` 를 거부하고(400, `deprecated for this model`),
`claude-haiku-4-5-20251001` 은 `output_config.effort` 를 거부한다. 단계별 설정은
`config.yaml: llm.{relevance_gate,extraction}` 에 나뉘어 있다 (D-018, D-033).

## 로컬 산출물 취급 — (가) 로컬 / 개발 기준

다음은 **프롬프트와 LLM 응답 본문이 평문으로 디스크에 남는** 저장소다.

| 경로 | 무엇이 남나 | `.gitignore` |
|---|---|---|
| `data/extractions/` | 추출 보존소 — 프롬프트 전문, 게이트 판정, 온톨로지 원본 | O (`data/`) |
| `data/corpus/` | export 산출물 JSONL·manifest | O (`data/`) |
| `observability/logs/` | 게이트 스킵 기록, 미등록 기업 큐 | O (`logs/`) |
| `eval/scores/` | judge 채점 결과 | O |

**커밋되지 않는 것과 디스크에 없는 것은 다르다.** 로컬 디스크·백업·화면 공유는
여전히 노출 경로다.

- **보존 기간:** 정해진 일수 없음. 필요 없다고 판단하면 지운다.
- **접근 권한:** 별도 통제 없음 — 로컬 파일시스템 권한을 따른다. 그 머신에 로그인할
  수 있는 주체가 곧 접근 주체다.
- **삭제:** `rm -rf data/extractions data/corpus` / `rm -rf observability/logs`.

⚠️ **이 기준 전체가 "공개 RSS/Atom 피드 자료만 넣는다"는 전제에 의존한다.** 사내
문서·고객 데이터를 투입하는 순간 이 기준은 **즉시 무효**이며, 보존 기간·접근 주체·
삭제 책임자를 정하는 것이 그 투입의 선행 조건이 된다.

## ADR 기록

- 되돌리기 비용이 있는 결정(새 의존성, 아키텍처 변경, 외부 API·서비스 선택,
  데이터 형식·식별자 규칙)을 내리면 `adr-recorder` 스킬로 `docs/adr/` 에 ADR 을
  남긴다.
- **스킬을 명시적으로 호출한다. Write/Edit 도구로 직접 쓰지 않는다.** 형식과 번호
  규칙이 스킬 안에 있어서, 직접 쓰면 그것이 맞는지 **검증하는 주체가 없어진다.**
  session-03 의 ADR-018·019 가 스킬을 거치지 않고 직접 작성됐고, 결과적으로 형식이
  맞았다는 사실이 오히려 문제다 — **틀렸어도 알 수 없었다.**
- **결정이 난 자리에서 남긴다.** 세션 끝에 몰아서 쓰면 검토했던 대안과 기각 사유가
  이미 흐려져 있고, ADR 에서 가장 값이 나가는 부분이 그 둘이다.
- 형식과 번호 규칙은 `docs/adr/README.md` 를 따른다 (`docs/adr/ADR-NNN-slug.md`).
- 기존 결정의 전제가 바뀌면 새 ADR 로 덮지 말고, 해당 ADR 에 Amendment 를 추가하고
  Review Trigger 상태를 갱신한다.
- 일상적인 설계 판단은 README 의 결정 로그(`D-XXX`)에 계속 남긴다. **둘의 경계는
  되돌리기 비용이다** — 판단을 되돌리는 데 재작업이 드는 것이 ADR 이다.

## 작업 원칙

### 프롬프트

- 실행에 쓰인 프롬프트 버전(예: `extract_ontology.v2.md`)은 **수정하지 않는다.**
  변경이 필요하면 새 버전 파일을 만든다 (D-010, D-023). 파일명 관례는
  `{용도}.{버전}.md` 이고 `extraction/prompts/README.md` 에 정리돼 있다.
- 통제어휘는 프롬프트에 하드코딩하지 않고 `schema.py` Enum 에서 런타임 주입한다
  (D-012).

### 스키마와 어휘

- 통제어휘(`extraction/schema.py` 의 Enum)와 `config.yaml` 의 미러는 항상 동기화
  상태를 유지하고, `tests/test_vocab_sync.py` 로 검증한다. `schema.md` 의 표도 같이
  고쳐야 하지만 그건 자동 검증 대상이 아니다.
- 어휘를 쪼개거나 이름을 바꾸면 **과거 노트의 라벨이 소급해서 틀린 것이 된다.**
  판단 기준이 바뀌는 정도라면 스키마가 아니라 문서·프롬프트 층에서 좁힌다 (D-022).
- 어휘는 **출력 계약의 정본**이기도 하다. MARA 는 복제하지 않고 매 export 의
  manifest 스냅샷과 대조하며, **값 삭제·개명·쪼개짐은 그쪽 import 실패**다.

### 결정 로그

- 새로운 설계 판단은 README.md 결정 로그에 `D-XXX` 형식으로 기록한다. 근거와
  검토했던 대안을 함께 남긴다.
- 판단을 번복할 때 **기존 항목을 지우지 않는다.** 상태를 `번복됨` / `부분 번복` 으로
  바꾸고 사유를 남긴 뒤, 새 결정을 별도 항목으로 추가한다 (예: D-003 → D-029).

### git

- main 에 직접 커밋하지 않는다. `feat/<주제>` 형식의 브랜치에서 작업한 뒤
  `git merge --ff-only` 로 병합한다.
- 커밋 메시지는 Conventional Commits 형식이고 **요약과 본문 모두 영어로** 쓴다
  (포트폴리오 공개 레포). 본문은 무엇을·왜를 2~4줄로, 관련 결정 로그 번호를 참조한다.
- 논리 단위로 커밋을 나눈다. 한 파일이 여러 단위에 걸치면 hunk 단위로 쪼개되,
  억지로 쪼개지 말고 가장 관련 있는 커밋에 합쳐도 된다.
- **push 는 사용자가 직접 확인 후 진행한다.** 커밋까지만 만들고 `git log --oneline` 을
  보여준 뒤 멈춘다.
- 셸 스크립트는 **LF 로 체크아웃되어야 한다** (`.gitattributes`). CRLF 로 받으면
  셔뱅이 깨져 훅이 **조용히 안 돈다** — 실패하지 않고 아무 일도 일어나지 않는다.

### 커밋 전 확인

매 커밋 직전에 staged 내용을 검사한다.

- `git status` 에 `.env` 가 없는지
- staged diff 에 API 키 패턴(`sk-ant-`), 개인 로컬 경로(`C:\`, Vault 디렉터리 이름,
  OS 사용자명)가 하드코딩돼 있지 않은지 grep 으로 재확인
- 커밋 author 이메일이 GitHub noreply 주소인지 (`git config user.email`). 공개
  레포의 커밋 메타데이터는 누구나 조회할 수 있고, 지우려면 히스토리 재작성이 필요하다
- 실행 산출물(`observability/logs/*.jsonl`, `eval/scores/*`, `data/`)이 잡히지
  않았는지

### 테스트

- 가상환경으로 돌린다: `.venv/Scripts/python.exe -m pytest tests/ -q`.
  시스템 파이썬에는 `feedparser` 등이 없어 수집 모듈 import 에서 깨진다.
- **실제 Obsidian Vault 에 절대 쓰지 않는다.** 모든 쓰기 테스트는 `tmp_path` 안에서만
  일어난다. 같은 이유로 관측 로그 테스트도 실제 `observability/logs/` 를 건드리지
  않는다 — 건드리면 `occurrence_count` 누적이 오염된다. export 보존소
  (`data/extractions/`)도 같다.
- **다른 레포를 테스트 입력으로 읽지 않는다.** MARA 코퍼스·골든셋이 필요한 테스트는
  `tmp_path` 에 그 모양을 흉내 낸 픽스처를 만든다. 남의 레포 파일이 바뀔 때 이쪽
  테스트가 깨지면, 두 레포가 코드를 공유하지 않는다는 전제가 테스트에서부터 깨진다.
- 동작을 의도적으로 바꿔 기존 테스트가 깨졌다면, 되돌리지 말고 테스트를 새 계약에
  맞게 갱신한다.
- **테스트는 루프백 밖으로 나가지 않는다.** `tests/conftest.py` 의 `no_outbound_network`
  가 전체 테스트에 무조건 걸려 있다(autouse). 실제 요청이 필요해 보이면 그건 목을
  거는 층이 틀린 것이다 — 트립와이어를 끄지 말고 층을 내린다.
- **변이 검사는 커밋되지 않은 작업본에 `git checkout` / `git restore` 를 쓰지 않는다.**
  임시 복사본이나 별도 worktree 에서 한다. 변이를 되돌리는 명령이 **같이 있던 미커밋
  변경까지 되돌린다** — 복구 지점이 없어 그 작업이 통째로 사라진다.

### eval / 골든셋

- **모델 출력은 정답이 아니다.** 파이프라인 실행 결과를 골든셋으로 승격하려면 사람이
  라벨링을 확정해야 한다. 그러지 않으면 eval 이 "모델이 스스로를 채점하는" 구조가 된다.
- 판단이 갈렸던 경계 사례를 우선 넣는다. 쉬운 건 100개보다 경계 사례 20개가 낫다.

## 세션 운영

개발은 **매번 새 세션에서** 한다. 세션이 갈리면 맥락이 끊기고, 그 끊김을 메우는
것이 handoff·ADR·`.claude/rules/` 다. **장치는 이미 있으므로 문제는 쓰는 방식에서
생긴다** — session-03 이 그랬다. 새 규칙 파일에 `paths:` 를 빠뜨려 매 세션 무조건
로드되게 만들었고, ADR 두 건을 스킬 없이 직접 썼다. **둘 다 장치가 없어서가 아니라
있는 장치를 관례 밖으로 쓴 경우다.**

### 시작

- `.claude/hooks/load-handoff.sh` (SessionStart)가 최신 `docs/handoff/session-NN.md`
  를 자동 로드한다. **들어오지 않았으면 훅이 조용히 안 돈 것이므로** 수동으로 최신
  파일을 읽고, 원인을 따로 확인한다 (셸 스크립트 CRLF 가 전례다).
- 새 작업은 **새 브랜치**에서 시작한다 (`feat/<주제>`). `main` 에 병합된 직전
  브랜치를 재사용하지 않는다.

### 진행 중

- **새 규칙 파일(`.claude/rules/*.md`)은 `paths:` 프론트매터를 먼저 정한 뒤 본문을
  쓴다.** 스코프가 없으면 매 세션 무조건 로드되어 그 파일만 컨텍스트 절약이 깨진다.
  기준은 **그 파일/디렉터리를 건드리거나, 그 파일이 목적지·파라미터를 정하는 곳**
  이고, 다른 규칙이 이미 덮는 범위를 또 넓게 잡지 않는다.
- ADR 은 **스킬로 남긴다** — 위 "ADR 기록" 참고.

### 종료

- `docs/handoff/session-NN.md` 를 남긴다. 완료된 것뿐 아니라 **막힌 것과 결정 대기
  항목**을 반드시 적는다.
- 리뷰·측정에서 나온 **미해결 항목은 handoff 의 결정 대기로 옮긴다.** 별도 문서에만
  두면 다음 세션이 그 파일을 열 이유가 없다.
- 커밋 전 확인은 위 "커밋 전 확인" 목록을 그대로 적용한다.

경로별 세부 컨벤션은 `.claude/rules/` 참고
(prompts / vocabulary / export / eval / **external-llm** / **vllm-endpoint**).

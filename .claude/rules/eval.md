# eval / 골든셋 컨벤션
- **모델 출력은 정답이 아니다.** 파이프라인 결과를 골든셋으로 승격하려면 사람이
  라벨링을 확정한다(`status: confirmed`, D-039). 그러지 않으면 eval 이 "모델이
  스스로를 채점하는" 구조가 된다.
- 판단이 갈렸던 경계 사례를 우선 넣는다. 쉬운 것 100개보다 경계 사례 20개가 낫다.
- 루브릭을 바꾸면 **대조군과 함께** 검증한다 (D-048). 대조군이 없으면 "루브릭이
  옮겼다"와 "judge 가 원래 흔들린다"를 가를 수 없다.
- 반복 채점을 표본 증가로 세지 않는다 (D-050).

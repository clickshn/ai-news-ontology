# eval / 골든셋 컨벤션
- **모델 출력은 정답이 아니다.** 파이프라인 결과를 골든셋으로 승격하려면 사람이
  라벨링을 확정한다(`status: confirmed`, D-039). 그러지 않으면 eval 이 "모델이
  스스로를 채점하는" 구조가 된다.
- 판단이 갈렸던 경계 사례를 우선 넣는다. 쉬운 것 100개보다 경계 사례 20개가 낫다.
- 루브릭을 바꾸면 **대조군과 함께** 검증한다 (D-048). 대조군이 없으면 "루브릭이
  옮겼다"와 "judge 가 원래 흔들린다"를 가를 수 없다.
- 반복 채점을 표본 증가로 세지 않는다 (D-050).
- **완결성 점수의 출처가 다른 행을 한 평균에 넣지 않는다.** v6 부터 점수는 judge 의
  요소 판정으로 **코드가** 계산한다(ADR-021). 결과 행의 `completeness_scored_by`
  (`judge`/`code`)를 먼저 보고, v5 이하와 직접 비교하지 않는다.
- **구조상 성립하는 값을 잰 값처럼 적지 않는다.** 코드가 보장하는 성질(요소 → 슬롯
  일관성 등)은 단위 테스트로 고정하고 결과에는 None 으로 둔다.

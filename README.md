# ai-news-ontology

AI 뉴스·논문·업계 소식을 자동 수집해 **온톨로지 스키마로 구조화**하고,
**LLM-judge 기반 eval 로 요약 품질을 검증**한 뒤, **Obsidian Vault 에 마크다운
노트로 적재**하는 개인 파이프라인.

> **현재 상태** — 수집 → 관련성 게이트 → 추출 → 기업명 정규화 → Obsidian 적재까지
> 한 건이 실제로 끝까지 흐르고, eval 채점기도 골든셋 1건으로 실제 점수를 냈다.
> **골든셋이 1건뿐이라 지표는 아직 추세가 아니라 관측치다.**
>
> | 단계 | 상태 |
> |---|---|
> | `collectors/` — RSS·Atom 수집, 소스별 본문 품질 표기 | 동작 |
> | 관련성 게이트 — Haiku 4.5, `temperature: 0` 고정 | 동작 |
> | 추출 — Opus 5, `extract_ontology.v3.md` | 동작 |
> | `extraction/normalize.py` — 기업명 alias 정규화 | 동작 |
> | `obsidian_writer/` — frontmatter + 위키링크 노트 적재 | 동작 |
> | `observability/` — 스킵·미등록 기업 JSONL 기록 | 동작 |
> | `eval/` — 골든셋 대조 + LLM-judge 채점기 | 동작 (골든셋 confirmed 1건, 첫 실행 완료) |
> | Langfuse trace, 토큰·비용 집계 | 미구현 |
>
> 골든셋은 **확정 1건 + 보류 1건**이다
> ([`eval/golden_set/README.md`](eval/golden_set/README.md)).

이 프로젝트의 작업 규칙(API 호출 승인, 프롬프트 버저닝, git·커밋 관례)은
**[`CLAUDE.md`](CLAUDE.md)** 참고.

## 왜 만드는가

AI 소식은 양이 많고 휘발성이 높다. 읽고 나면 남지 않는다. 이 파이프라인의 목표는
"많이 읽는 것"이 아니라 **나중에 다시 찾을 수 있는 형태로 남기는 것**이다.
그래서 두 가지를 고집한다.

1. **구조화** — 자유 텍스트 요약만 쌓으면 검색이 안 된다. 고정된 축(기술영역,
   발표유형 등)으로 태깅해야 "작년에 봤던 RAG 관련 오픈소스 발표"를 찾을 수 있다.
2. **검증** — LLM 요약은 그럴듯하게 틀린다. 골든셋과 LLM-judge 로 품질을 측정하지
   않으면, 조용히 나빠지는 것을 알아챌 방법이 없다.

## 아키텍처

```
┌──────────────┐
│  외부 소스    │  RSS 피드 / arXiv API
└──────┬───────┘
       │
       ▼
┌──────────────────────────────────────────────┐
│ collectors/                                  │  판단 없음. 원문만 가져온다.
│  rss.py · arxiv.py · dedup.py                │
└──────┬───────────────────────────────────────┘
       │ RawItem(url, title, body, source, published_at)
       ▼
┌──────────────────────────────────────────────┐
│ extraction/                                  │  LLM 호출 지점 ①
│  extractor.py ──▶ LLMClient (llm.py)         │
│  normalize.py  기업명 alias 정규화            │
│  schema.py     ★ 온톨로지 SSoT               │
└──────┬───────────────────────────────────────┘
       │ NewsNote  (pydantic 검증 통과분만)
       │
       ├──────────────────────────┐
       ▼                          ▼
┌──────────────────────┐   ┌──────────────────────────┐
│ eval/                │   │ obsidian_writer/         │
│  golden_set/  정답    │   │  template.py  frontmatter │
│  judge_prompts/ 루브릭 │   │  linking.py   [[위키링크]] │
│  runner.py    채점    │   │  writer.py    원자적 쓰기  │
│  → scores/ (gitignore)│   └──────────┬───────────────┘
└──────────────────────┘              │
        │  LLM 호출 지점 ②             ▼
        │                      ┌──────────────────┐
        │                      │ Obsidian Vault   │
        │                      │ (.env 로 경로 주입)│
        │                      └──────────────────┘
        ▼
┌──────────────────────────────────────────────┐
│ observability/   trace · 토큰/비용 · 실패 로그  │  전 단계를 가로지름
└──────────────────────────────────────────────┘
```

검증 실패(ValidationError, 임계값 미달)는 **노트를 쓰지 않고 격리**한다.
조용히 통과시키면 Vault 가 오염되고, 그때부터 이 시스템은 신뢰할 수 없어진다.

## 폴더별 역할

| 경로 | 역할 |
|---|---|
| `collectors/` | RSS·arXiv 수집, 중복 제거. **요약·분류하지 않는다** |
| `extraction/` | 요약 + 온톨로지 5필드 구조화. `schema.py` 가 스키마 SSoT |
| `eval/` | 품질 검증. 골든셋 대조(결정적) + LLM-judge(요약) |
| `eval/golden_set/` | 사람이 라벨링한 정답. **커밋 대상** |
| `eval/judge_prompts/` | judge 루브릭. 버전 고정, 수정 대신 v2 생성 |
| `eval/scores/` | 실행 결과. **gitignore** |
| `obsidian_writer/` | Vault 마크다운 적재. frontmatter + 위키링크 |
| `observability/` | trace, 토큰/비용, 실패 로그. Langfuse 없으면 no-op |
| `tests/` | 계약 테스트 (어휘 동기화, 스키마 round-trip) |

루트 파일: `config.yaml`(비밀 아닌 설정) · `.env.example`(비밀) ·
`schema.md`(스키마 문서) · `pyproject.toml`

## 시작하기

```bash
python -m venv .venv && .venv\Scripts\activate   # Windows
pip install -e ".[dev]"

cp .env.example .env      # ANTHROPIC_API_KEY, OBSIDIAN_VAULT_PATH 채우기
```

설정은 두 곳으로 나뉜다.
- **`.env`** — 비밀과 머신별 경로. 커밋하지 않는다.
- **`config.yaml`** — 소스 목록, 통제어휘, 임계값. 커밋하고 리뷰한다.

## 온톨로지 스키마

5개 필드: `기술영역`(통제어휘 14) · `발표유형`(통제어휘 6) · `관련기업`(자유 +
alias 정규화) · `관련기존기술`(자유 태그) · `영향도`(1~5 + 근거).

전체 정의와 판단 기준은 **[`schema.md`](schema.md)**,
코드 정의는 **[`extraction/schema.py`](extraction/schema.py)**.
두 문서는 1:1 대응하며 `tests/test_vocab_sync.py` 가 일치를 검증한다.

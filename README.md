# ai-news-ontology

AI 뉴스·논문·업계 소식을 자동 수집해 **온톨로지 스키마로 구조화**하고,
**LLM-judge 기반 eval 로 요약 품질을 검증**한 뒤, **Obsidian Vault 에 마크다운
노트로 적재**하는 개인 파이프라인.

> 설계 판단의 배경과 근거는 **[`INTERVIEW_NOTES.md`](INTERVIEW_NOTES.md)** 에
> `상황 → 판단 → 근거 → 결과` 형식으로 8건 정리해 두었다.

## 왜 만드는가

AI 소식은 양이 많고 휘발성이 높다. 읽고 나면 남지 않는다. 이 파이프라인의 목표는
"많이 읽는 것"이 아니라 **나중에 다시 찾을 수 있는 형태로 남기는 것**이다.
그래서 두 가지를 고집한다.

1. **구조화** — 자유 텍스트 요약만 쌓으면 검색이 안 된다. 고정된 축(기술영역,
   발표유형 등)으로 태깅해야 "작년에 봤던 RAG 관련 오픈소스 발표"를 찾을 수 있다.
2. **검증** — LLM 요약은 그럴듯하게 틀린다. 골든셋과 LLM-judge 로 품질을 측정하지
   않으면, 조용히 나빠지는 것을 알아챌 방법이 없다.

## 이 프로젝트가 다루는 것

LLM 을 호출하는 코드는 짧다. 이 레포의 대부분은 **그 출력을 믿을 수 있게 만드는
장치**다.

| | 무엇을 | 어떻게 |
|---|---|---|
| **비용 구조 설계** | 비싼 모델에 버려질 일을 시키지 않는다 | 저비용 관련성 게이트를 앞단에 두되, **게이트에 분류는 시키지 않는다** — 두 모델의 출력이 섞이면 어느 쪽 품질을 재는지 알 수 없어진다 |
| **평가 거버넌스** | "모델이 스스로를 채점하는" 구조를 코드로 막는다 | 골든셋에 `draft`/`confirmed` 상태를 두고 로더가 `confirmed` 만 읽는다. 승격 조건은 pydantic 검증이 강제한다 |
| **온톨로지 운영** | 어휘를 확장하되 과거 라벨을 소급 오염시키지 않는다 | 값 **추가**는 스키마에서, 판단 **기준**은 문서·프롬프트 층에서. 어휘를 쪼개면 이미 쌓인 노트가 소급해서 틀려진다 |
| **재현성** | 점수가 움직였을 때 원인을 좁힐 수 있게 한다 | 실행에 쓰인 프롬프트는 수정하지 않고 버전을 올린다(현재 7개 보존). 채점 결과에 프롬프트 파일명 + SHA256 + 토큰 사용량을 함께 저장한다 |
| **오류의 방향** | 되돌릴 수 있는 실수와 없는 실수를 다르게 다룬다 | 게이트는 재현율 우선(잘못 버리면 영영 사라진다), 기업명 정규화는 정밀도 우선(잘못 합치면 되돌릴 수 없다) |

## 현재 상태

수집 → 관련성 게이트 → 추출 → 기업명 정규화 → Obsidian 적재까지 한 건이 실제로
끝까지 흐르고, eval 채점기도 골든셋 1건으로 실제 점수를 냈다.

| 단계 | 상태 |
|---|---|
| `collectors/` — RSS·Atom 수집, 소스별 본문 품질 표기 | 동작 |
| 관련성 게이트 — Haiku 4.5, `temperature: 0` 고정 | 동작 |
| 추출 — Opus 5, `extract_ontology.v4.md` | 동작 |
| `extraction/normalize.py` — 기업명 alias 정규화 | 동작 |
| `obsidian_writer/` — frontmatter + 위키링크 노트 적재 | 동작 |
| `observability/` — 스킵·미등록 기업 JSONL 기록 | 동작 |
| `eval/` — 골든셋 대조 + LLM-judge 채점기 | 동작 (골든셋 confirmed **2건**) |
| `eval/analysis.py` — 반복 채점 분포·슬롯 판정 집계 | 동작 |
| Langfuse trace, 토큰·비용 집계 | 미구현 |

| 2 | judge 와 사람의 완결성 격차는 자기 편향이 아니라 **서로 다른 것을 세고 있었던 것** — 누락 목록이 합집합 6개 중 1개만 겹쳤다 | 그래서 구간 세분화보다 먼저 "무엇이 핵심인가"(4슬롯)를 정의했다. 표본 1건으로 편향을 주장하지 않는다 | D-043 · D-045 |
| 2-1 | 그 루브릭을 **사전 등록 기준 + 대조군**으로 검증했다 — 가설·임계값을 데이터 전에 고정하고 구 루브릭을 함께 돌렸다 | 대조군이 없으면 "루브릭이 옮겼다"와 "judge 가 원래 흔들린다"를 못 가른다. 결과는 v3 8/8 회 2점 · v2 5/5 회 3점, **슬롯 판정까지 8/8 일치** | D-048 · D-049 |
| 3 | 정밀 추출 앞에 저비용 게이트를 두되 **게이트에 분류는 시키지 않는다** | 두 모델의 출력이 섞이면 어느 쪽 품질을 재는지 알 수 없어진다. 비용 최적화가 측정 가능성을 깨면 안 된다 | D-015 · D-017 |
| 4 | 기업명 정규화에 **퍼지 매칭을 쓰지 않는다** | 미탐은 원문이 보존돼 복구되지만 오탐은 서로 다른 기업을 한 노드로 합치고 되돌릴 수 없다. 게이트와 정반대 방향 | D-025 · D-026 |
| 5 | 어휘에 **값 추가는 스키마**(`Community/Discussion`), **판단 기준은 문서·프롬프트** (`Agent` 를 쪼개지 않음) | 값을 추가하면 과거 라벨이 유효하지만, 값을 쪼개면 이미 쌓인 노트가 소급해서 틀린 것이 된다 | D-021 · D-022 |
| 6 | 골든셋에 `draft`/`confirmed` 를 두고 **로더가 `confirmed` 만 읽는다** | 초안이 섞이면 점수는 높게 나오고 그 사실이 어디에도 드러나지 않는다. 조용히 틀리는 오류는 코드로 막는다 | D-039 |
| 7 | 자유 태그 표기 통일에 **사전이 아니라 프롬프트 규칙**을 쓴다 | 어휘 규모를 모르는 채 사전을 만들면 틀린 사전이 되고 유지비를 감당할 수 없다. 닫힌 어휘는 사전, 열린 어휘는 규칙 | D-020 · D-024 |
| 8 | 필드마다 **채점 방식이 다르다** — 다중값은 Jaccard, 순서형은 ±1 부분점수, 자유 태그는 임계값에서 제외 | 정답 집합이 닫히지 않는 필드를 accuracy 에 넣으면 지표가 거짓말을 한다 | D-040 |
| 9 | 실행에 쓰인 프롬프트는 **수정하지 않고 버전을 올린다.** 점수에 파일명 + SHA256 을 함께 남긴다 | 프롬프트가 바뀌면 점수도 바뀐다. 어느 버전에서 나온 점수인지 모르면 eval 자체가 의미를 잃는다 | D-010 · D-041 · D-045 |
| 10 | 관측은 **선택적 의존성**이고, 두 로그의 쓰기 방식이 다르다 (감사 로그 = append-only, 작업 큐 = upsert) | 관측 실패가 파이프라인 실패가 되면 안 된다. 목적이 다르면 쓰기 방식도 다르다 | D-008 · D-036 |

## 폴더별 역할

| 경로 | 역할 |
|---|---|
| `collectors/` | RSS·Atom 수집. **요약·분류·필터링하지 않는다** |
| `extraction/` | 게이트 + 요약 + 온톨로지 5필드 구조화. `schema.py` 가 스키마 SSoT |
| `eval/` | 품질 검증. 골든셋 대조(결정적) + LLM-judge(요약) |
| `eval/golden_set/` | 사람이 라벨링한 정답. **커밋 대상** |
| `eval/judge_prompts/` | judge 루브릭. 버전 고정, 수정 대신 새 버전 생성 |
| `eval/scores/` | 실행 결과. **gitignore** |
| `obsidian_writer/` | Vault 마크다운 적재. frontmatter + 위키링크 |
| `observability/` | 스킵·미등록 기업 JSONL, 비용 실측. 꺼져 있으면 no-op |
| `tests/` | 계약 테스트 — 어휘 동기화, 프롬프트 규칙, 채점 로직 |

루트 파일: `config.yaml`(비밀 아닌 설정) · `.env.example`(비밀) ·
`schema.md`(스키마 문서) · `CLAUDE.md`(작업 규칙) · `pyproject.toml`

## 시작하기

```bash
python -m venv .venv && .venv\Scripts\activate   # Windows
pip install -e ".[dev]"

cp .env.example .env      # ANTHROPIC_API_KEY, OBSIDIAN_VAULT_PATH 채우기
pytest tests/ -q          # 261 passed — API 호출 없음
```

```bash
# 수집 -> 게이트만 (저비용)
python -m extraction.extractor --source GeekNews --gate-only

# 수집 -> 게이트 -> 정밀 추출
python -m extraction.extractor --source GeekNews --index 0

# 골든셋 대조만 (API 호출 없음)
python -m eval.runner --predictions <preds.jsonl> --no-judge
```

설정은 두 곳으로 나뉜다.
- **`.env`** — 비밀과 머신별 경로. 커밋하지 않는다.
- **`config.yaml`** — 소스 목록, 단계별 모델, 통제어휘, 임계값. 커밋하고 리뷰한다.

작업 규칙(실제 API 호출 전 승인, 프롬프트 버저닝, git 관례)은
**[`CLAUDE.md`](CLAUDE.md)** 참고.

## 온톨로지 스키마

5개 필드: `기술영역`(통제어휘 14) · `발표유형`(통제어휘 7) · `관련기업`(자유 +
alias 정규화) · `관련기존기술`(자유 태그) · `영향도`(1~5 + 근거). 여기에 노트 본문용
`요약`(2~3문장)이 더해진다.

전체 정의와 판단 기준은 **[`schema.md`](schema.md)**,
코드 정의는 **[`extraction/schema.py`](extraction/schema.py)**.
두 문서는 1:1 대응하며 `tests/test_vocab_sync.py` 가 일치를 검증한다.

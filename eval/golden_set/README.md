# eval/golden_set/

사람이 직접 라벨링한 정답 세트. **커밋 대상**이며 이 프로젝트에서 가장 오래 남는 자산.

## 형식
한 건 = 파일 하나(`{yyyymmdd}-{slug}.json`) 또는 `golden.jsonl` 한 줄.
파일 단위를 기본으로 한다 — diff 리뷰가 쉽고 충돌이 적다.

```json
{
  "id": "20260829-anthropic-claude-opus-5",
  "source_url": "https://example.com/post",
  "input": { "title": "...", "body": "..." },
  "expected": {
    "기술영역": ["LLM", "Reasoning"],
    "발표유형": "ProductLaunch",
    "관련기업": ["Anthropic"],
    "관련기존기술": ["Transformer"],
    "영향도": { "점수": 4, "근거": "..." }
  },
  "reference_summary": "사람이 쓴 3~5문장 요약 (judge 의 참조용, 정답 아님)",
  "human_summary_scores": { "충실성": 5, "완결성": 4, "간결성": 4 },
  "labeled_by": "clickshn",
  "labeled_at": "2026-08-29",
  "notes": "판단이 갈렸던 지점 기록"
}
```

## 골든셋 후보 (검토 대기)

> **모델 출력은 정답이 아니다.** 아래는 파이프라인 실행 결과일 뿐이며,
> 사람이 검토해 라벨을 확정한 뒤에만 골든셋 파일로 승격한다. 모델 출력을
> 그대로 정답으로 삼으면 eval 이 "모델이 스스로를 채점하는" 구조가 된다.

| 날짜 | 항목 | 실행 | 상태 |
|---|---|---|---|
| 2026-08-29 | GeekNews `바이브코딩으로 만든 퍼저가 FFmpeg의 0 나누기 버그를 발견` ([#33001](https://news.hada.io/topic?id=33001)) | gate(Haiku) → extract **v1 → v2 재추출 완료** | **확정 후보** (아래 판단 참고) |
| 2026-08-29 | GeekNews `SpaceX의 Cursor 인수 이후 OpenAI가 내린 결정` ([#33003](https://news.hada.io/topic?id=33003)) | gate(Haiku) → extract v2 | **보류** — `발표유형` 이견 있음 |

확정 절차: 위 항목을 사람이 라벨링 → 아래 형식의 JSON 파일로 저장 →
`notes` 에 모델 출력과 다른 부분과 그 이유를 남긴다.

### #33001 (FFmpeg) — v1 → v2 재추출 결과

D-020·D-021·D-022 세 규칙이 **모두 라벨을 바꿨다.**

| 필드 | v1 | v2 |
|---|---|---|
| 기술영역 | `Application/Product`, `Agent` | `Application/Product` |
| 발표유형 | `Benchmark/Report` | `Community/Discussion` |
| 관련기존기술 | `퍼징(Fuzzing)`, `바이브코딩` | `Fuzzing`, `Vibe Coding` |
| 영향도 | 2 | 2 (근거 표현만 다름) |

**판단: 정답으로 확정할 만하다.** 네 필드 모두 문서화된 기준에 부합한다.
다만 확정 전에 사람이 확인할 것 —
- `영향도 2` 가 적정한가. v1/v2 가 모두 2를 냈지만 두 판정 모두 같은 모델이라
  일치가 근거가 되지 못한다. **사람 점수를 따로 매겨 `human_summary_scores` 에 남길 것.**
- `관련기업` 에 `FFmpeg`(오픈소스 프로젝트)이 들어간 채로 둘지 → 아래 "관찰 필요" 참고.

### #33003 (OpenAI/Cursor) — 보류 사유

`발표유형: Funding/M&A` 로 나왔으나 기사의 1차 사건은 **인수 자체가 아니라
인수 이후 OpenAI 의 모델 공급 계약 종료**다. 어휘 7개 중 "기업 간 계약·공급
중단"에 맞는 값이 없어 인접 값으로 밀린 것으로 보인다 — D-021 때와 같은 형태의
빈 칸일 가능성이 있다. **사례가 더 쌓이기 전에는 정답으로 확정하지 않는다.**

`역할: 경쟁사`(SpaceX)도 부정확하다. SpaceX 는 Cursor 의 인수 주체이므로
`인수 주체` 가 맞다. 프롬프트가 제시한 역할 예시에 `인수 주체` 가 없어서
인접 값으로 밀렸을 가능성이 있다.

## 관찰 필요 — 판단 보류 중인 것

사례가 더 쌓여야 결정할 수 있는 것들. 지금 스키마를 바꾸지 않고 기록만 한다.

| 관찰 대상 | 발단 | 재검토 조건 |
|---|---|---|
| `CompanyRef` 가 기업이 아닌 **오픈소스 프로젝트**를 수용하는 사례 | 2026-08-29 첫 추출에서 `FFmpeg`(프로젝트)이 `관련기업` 에 들어옴 | 유사 사례 10건 이상 누적 시, 필드명을 `관련조직` 류로 넓힐지 / 엔티티 종류 필드를 둘지 재검토 |
| `role`(역할) 자유서술의 어휘 다양성 | 같은 실행에서 `영향 대상` 이 나옴 — 프롬프트가 제시한 5개 예시(`발표 주체`/`인수 대상`/`투자자`/`경쟁사`/`협력사`) 밖의 값 | 서로 다른 role 값이 10종 이상 누적 시, 통제어휘로 닫을지 판단 |
| ~~`canonical` 승계 로직이 실제로 쓰이는지~~ | **2026-08-29 확인 완료.** 모델 원본 JSON 에 `정규명` 키가 아예 없었다(4개 엔티티 전부) → validator 의 raw 승계가 동작 중 | 해결. 대신 아래 "정규화 미구현" 항목으로 이어짐 |
| ~~alias 정규화가 아예 미구현~~ | `OpenAI` 가 등록돼 있는데도 `정규화성공=false` 였다 | **2026-08-29 해결** (D-025). 캡처된 JSON 재검증에서 `OpenAI` → `정규화성공=true` 확인. **#33003 을 골든셋으로 확정할 때는 이 값을 true 로 적을 것** |
| 미등록 엔티티 누적 | 첫 2건에서 `FFmpeg`·`Cursor`·`SpaceX` 가 미등록 | `company_aliases` 에 추가할지 판단. `Cursor`·`SpaceX` 는 기업이라 추가가 자연스럽고, `FFmpeg` 은 프로젝트라 위 항목과 함께 판단 |
| ~~게이트 판정 비결정성~~ | #33001 이 5회 중 4통과/1스킵으로 갈렸다 | **2026-08-29 해결** (D-032). 원인은 `temperature` 미설정(API 기본 1.0). `temperature: 0` 고정 후 5회 재실행에서 판정·근거가 바이트 단위로 동일. 이 항목은 "판정 경계 사례"가 아니라 **설정 결함**이었다 |
| `역할` 어휘에 빈 칸 | `SpaceX`(인수 주체)가 `경쟁사` 로 분류됨. 프롬프트 예시 5개에 `인수 주체` 가 없다 | role 값 10종 누적 시 함께 판단 |

## 라벨링 규칙
- **애매했던 건을 우선 넣는다.** 쉬운 건 100개보다 경계 사례 20개가 낫다.
- `기술영역`이 3개를 넘으면 그건 기사가 아니라 주간 요약이다 — 골든셋에서 제외.
- `notes` 에 "왜 이 라벨인지"를 남긴다. 나중의 나와 judge 루브릭이 이걸 참고한다.
- 목표 규모: 1차 30건, 2차 100건.
